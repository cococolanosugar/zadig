## 1. 审查背景与穿透核查成果

本轮为用户指示的「十轮全流程逆向交叉循环特战」第六轮（Loop 06），聚焦发布计划（ReleasePlan）与版本交付物（Delivery）模块：发布全生命周期状态机映射、定时/预约发布接口、以及交付物制品富元数据详情端点。

经 ZCode 深入后端状态机枚举与接口协议对账，主控独立交叉核验确证：
- **LOOP6-B1 (B 类 · 关键运行缺陷 · 发布状态机枚举缺失)**：
  - 后端发布计划全生命周期定义了 16 种合法状态（`pkg/microservice/aslan/config/consts.go:674-700`），包括 `success`, `executing`, `failed`, `denied`, `timeout`, `cancel`, `finish_planning`, `wait_for_approval`, 以及 6 种 `wait_for_*` 外部确认状态；
  - 原前端在表格列和详情顶部 Tag 中仅映射了 4 种基础状态（`success`, `executing`, `failed`, 默认），导致审批驳回（`denied`）、窗口超时（`timeout`）、已终止（`cancel`）、待执行（`finish_planning`）以及外部确认中等关键业务状态全部落入 default 分支被误显为“规划中（planning）”，严重破坏运维发布排期的真实状态可见度；
  - 任务 Job 状态列表中，缺少 `timeout`（超时）与 `cancel`（终止）状态映射。
- **LOOP6-B2 (B 类 · 关键端点缺失 · 预约/定时执行)**：
  - 后端提供 `POST /api/aslan/release_plan/plan/:id/schedule_execute`（`schedule_execute_time` 秒级时间戳），前端 API 层此前未定义该端点，无法满足指定发布窗口自动触发执行的诉求。
- **LOOP6-B4 (B 类 · 交付物详情端点缺失)**：
  - 后端交付中心提供 `GET /api/aslan/delivery/artifacts/:id` 接口用于查询制品 digest、架构和构建分层富元数据，前端 API 层此前仅有按镜像名检索接口，缺少按交付物 ID 获取详情的端点。
