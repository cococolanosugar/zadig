## 1. 审查背景与对账结论

本轮对实时执行与 Web 终端四条通信链路做"后端协议 → 前端消费"逐帧对账。

**对账总判定**：
- **无 A 类（功能阻断/契约断裂）缺口**——SSE 六端点、PodExec WS 三变体、帧协议逐字段对齐；
- **发现 1 项 B 类行为缺陷（LOOP4-B1 EOF 触发重连导致日志重复刷屏）**与 1 项 B 类功能缺口（LOOP4-B2 全量归档日志接口未接）；
- xterm 渲染/fitAddon/scrollback 主链完好，大流限频与搜索为 C 类增强。

## 2. 四大穿透核查点结论

### 审查点 1：实时日志流 SSE 协议契约与流式解析 — ⚠️ 契约对齐但 EOF 语义误判（B 类）

**后端协议（权威证据）**：
- 六条 SSE 日志端点（log/handler/router.go:41-46）：pods/testing/scanning/delivery/v4-workflow/jenkins；
- `GetWorkflowJobContainerLogsSSE`（handler/sse.go:136-158）：taskID/lines 路径参数 + `internalhandler.Stream`；
- `Stream`（**pkg/shared/handler/sse.go:31-65**）：gin `c.SSEvent("message", msg)` 标准帧（`event: message\ndata: <json>`）；producer 关闭 streamChan 后 `c.Stream` 返回 false → **连接正常关闭（EOF），无显式 done 事件**；`CloseNotify` 断连时 cancel 生产者。

**前端现状**：
- `utils/sse.ts`（R7 重写版）：`done`（服务端正常关流）与网络错误**一律进入重连判定**，默认 `autoReconnect=true, maxRetries=5`；
- **LOOP4-B1**：`LogViewer.tsx:144` 订阅日志流**未传 `autoReconnect:false`** → 任务结束/服务端正常关流后，前端按指数退避重连 5 次；每次重连成功都会重新拉取 `tails=1000` 历史日志并 `term.writeln` **重复写入全部历史行**（:154），造成日志重复刷屏 + 5 次冗余请求，最终 onError 仅打印"[日志流已结束]"（:161-163）。
- 佐证：`workflowTasks/running|pending` 列表订阅（workflow.ts:686/700）重连属预期行为 ✓；本轮已核其余订阅点（Quality:363、Delivery streamUrl→LogViewer）同受影响。

**修复建议（二选一，推荐双保险）**：
1. `LogViewer.tsx:144` 订阅选项增加 `autoReconnect: false`（日志流为一次性窗口流，EOF 即结束）；
2. `utils/sse.ts` 语义修正：`connect()` 中 `done` 分支不再调用 `scheduleReconnect`，改为**正常结束**（可选回调 `onComplete`），仅网络错误/HTTP 异常走重连——从根上区分"EOF"与"断线"，对应规范问点"任务结束标识识别"。

### 审查点 2：终端 WebSocket 握手与协议帧 — ✅ 逐字段对齐（无缺口）

- 端点三变体（aslan rest router.go:172-174）：`GET /api/podexec/:productName/:podName/:containerName/podExec/:envName`、`/production/` 前缀、`/debug/:workflowName/:jobName/task/:taskID`；前端 PodTerminal:203 拼接完全一致（含 projectName/token query）✓；
- 帧结构 `TerminalMessage{operation,data,rows,cols}`（**ws_terminal.go:54-59**）⇄ 前端同名接口（PodTerminal:54-58）✓；
- 帧纪律：前端仅发送 `stdin`（:262-263、初始化 `bash \r` :221-222）与 `resize`（:207-209，rows/cols 字段对齐 `remotecommand.TerminalSize{Width: Cols, Height: Rows}`）；后端 `unknown message type` 直接 EndOfTransmission 断连（ws_terminal.go:148-150）——**前端未发送 heartbeat 等未知帧**（R3 铁律复验保持）✓；
- 输出帧：后端 `stdout` + SecretEnvs 脱敏（Write 方法）⇄ 前端仅消费 `stdout`（:230/:240）✓。

### 审查点 3：xterm.js 渲染与内存防护 — ✅ 主链完好（1 项 C 类增强）

- 初始化：`Terminal{theme, fontFamily, fontSize, scrollback:10000, disableStdin}`（LogViewer:109-119）+ `FitAddon` + window resize 监听 + 全屏切换 refit（:99-104）✓；
- 缓冲防护：`scrollback: 10000` 上限兜底 + `rawLogsBufferRef` 内存副本分离 ✓；xterm 为 canvas 渲染，万行级不卡 DOM ✓；
- **LOOP4-C1（C 类增强）**：SSE onMessage 逐条 `term.writeln` 无批量 flush/限频——高频日志（每秒数百行）下可能掉帧。建议：引入 200ms 批量缓冲（`requestAnimationFrame` 或 timer 聚合后一次 `write(lines.join('\n'))`）。

### 审查点 4：历史日志全量下载与搜索过滤 — ⚠️ 1 项 B 类功能缺口

- 实时窗口内 copy/download ✓（LogViewer:68-97，基于 buffer Blob 导出）；
- **LOOP4-B2（B 类）**：全量归档日志接口 `GET /api/aslan/logs/log/v4/workflow/...`（log/handler/router.go 日志组，服务端持久化归档）**前端零消费**（grep 零命中）——用户只能获取当前 tails 窗口（默认 1000 行）内日志，任务结束后无完整日志回看/下载通道。**建议**：`api/workflow.ts` 封装 `getWorkflowV4HistoryLogs`，Execution/LogViewer 增加「下载完整日志」按钮走归档接口；
- **LOOP4-C2（C 类增强）**：LogViewer 无关键字搜索/高亮（grep 零命中）。建议：接入 `@xterm/addon-search`（或简易关键字过滤输入），与既有工具栏（复制/下载/全屏）并列。

## 4. 总结

1. **协议层（SSE 帧 / WS 帧 / 三变体端点 / query 契约）前后端逐字段对齐，A 类为零**；PodTerminal 终端帧纪律（仅 stdin/resize、无 heartbeat）经复验保持，规避了后端 unknown-operation 断连风险；
2. 唯一行为级缺陷 LOOP4-B1 源于 R7 重连韧性与日志流 EOF 语义的**组合误判**——修复成本极低（1 行选项 + sse.ts 语义修正），但用户可感知度高（日志重复刷屏），建议优先处理；
3. LOOP4-B2 为功能性补齐（归档日志下载），与前序审计"日志子域剩余项"结论一致，本轮已给出文件级行号证据；
4. C1/C2 为纯体验增强，不阻塞。
