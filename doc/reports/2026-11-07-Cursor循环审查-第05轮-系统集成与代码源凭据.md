## 2. A 类真实缺陷清单

### P0

#### R5-A1 · 集群缓存一键清理失败仍提示成功（A · P0）

- **位置**：`Settings/Clusters/ClusterCleanCacheModal.tsx:59-62`
  ```ts
  } catch {
    setCleaned(true);
    feedback.message.success('集群缓存清理指令已下发...');
  }
  ```
- **对照**：同轮第 04 轮 R4-A3 同类反模式；`POST /system/cleanCache/oneClick|sharedStorage` 失败时用户得到成功态与 `cleaned` UI
- **建议**：catch → `message.error`；勿置 `cleaned=true`；保留 `skipErrorHandler` 时必须显式展示后端 description

### P1

#### R5-A2 · CodeHost 缺 Validate + PATCH 更新 + OAuth 闭环（A · P1）

| L3（`codehost/handler/router.go`） | 前端 |
| --- | --- |
| `POST /api/v1/codehosts/validate` | ❌ 无 API 封装、无「测试连接」 |
| `PATCH /:id` `UpdateSystemCodeHost` | ❌ 仅 create/delete |
| `GET /:id/auth` `AuthCodeHost` | ❌ 表单有 `oauth` 选项但无跳转认证 |
| `GET /:id` | ❌ |

- **位置**：`settings.ts:246-266`；`CodeHosts/index.tsx`（创建 Modal 仅 Token 字段，`:170-175` Access Token 恒 required，OAuth Application 字段未条件渲染）
- **建议**：封装 `validateCodeHost` / `updateCodeHost` / `authCodeHost`；表单按 `auth_type` 切换 Token vs AppId/Secret；OAuth 创建后引导 `/codehosts/:id/auth`

#### R5-A3 · S3 / DBInstance / HelmRepo：有 Validate+PUT，页面无测试连接且无编辑（A · P1）

| 资源 | L3 Validate | L3 Update | API 层 | 页面 |
| --- | --- | --- | --- | --- |
| S3 | `POST /s3storage/validate` | `PUT /:id` | 仅 create/delete（**无 validate/update**） | Storage 仅增删；`is_default` 仅创建时可勾，无「设为默认」行操作 |
| DB | `POST /dbinstance/validate` | `PUT /:id` | 仅 create/delete | DBInstances 仅增删 |
| Helm | `POST /helm/validate` | `PUT /:id` | **有** `validateHelmRepo`，**无** update | ChartRepos **未调用** validate；无编辑 |

- **影响**：凭据改密/改 endpoint 只能删建；无法预检连通即写入
- **建议**：`settingsApi` 补 `validateStorage`/`updateStorage`/`validateDBInstance`/`updateDBInstance`/`updateHelmRepo`；各 ModalForm 增加测试连接 + 行内编辑；S3 对齐 Registry 的「设为默认」

#### R5-A4 · 模式性吞错：`catch { // Handled }` / `return false` 无错误反馈（A · P1）

| 文件 | 行号（约） | 行为 |
| --- | --- | --- |
| `CodeHosts/index.tsx` | 19-20, 38-39 | 删除/创建失败静默 |
| `Storage/index.tsx` | 19-20, 37-38 | 同上 |
| `DBInstances/index.tsx` | 19-20, 38-39 | 同上 |
| `ChartRepos/index.tsx` | 19-20, 36-37 | 同上 |
| `Registries/index.tsx` | 74-76, 101-102 | 删除/创建失败静默（设默认与 validate 有 error） |
| `Clusters/index.tsx` | 84-86, 101-102 | 删除/创建失败静默（依赖「拦截器已处理」假设，与 `skipErrorHandler` 场景不一致） |
| `KeyVault/index.tsx` | 33-34, 155-156 | 删除静默；列表 catch→空表 success |

- **建议**：统一 `feedback.message.error(err?.response?.data?.description \|\| err?.message)`；ProTable `request` 失败时 `success: false`

#### R5-A5 · Integration 大厅：多数类目「测试连接」退化成列表 GET；行级检测不带 encryptedKey（A · P1）

- **位置**：
  - 表单测试：`Integration/index.tsx:315-318` — 非 project/config/scanner/ci 时 `GET buildListUrl` 冒充连通成功
  - 行级检测：`:477-479` — `http.get(currentCategory.apiEndpoint)` **不附** `encryptedKey`，对 codehosts/connectors/cloud_service/external 易误失败或误成功
- **L3 真 validate 未接线示例**：`im_app/validate`、`observability/validate`、`api_gateways/validate`、`cloud_service/validate`、`llm/integration/validate`、`codehosts/validate`
- **建议**：按分类映射真实 validate body；行级检测对单条配置 POST validate，禁止「列表可达=凭据有效」

#### R5-A6 · KeyVault 独立页缺 Update；与 `systemConfigApi` 双轨（A · P1/P2）

- **L3**：`PUT /keyvault/items/:id`、`DELETE /groups/:group`
- **现状**：`Settings/KeyVault/index.tsx` 仅 POST 新建 + DELETE；**未**使用已封装的 `systemConfigApi.updateKeyVaultItem`（Config 页已有完整 KV CRUD）
- **建议**：独立页接入 update/edit Modal；或收敛为单一入口避免双实现漂移
