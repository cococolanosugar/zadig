## 1. 本轮审查与发现

本轮聚焦 **服务管理与配置中心 (Services & Configs)**，Cursor 独立审计并由主控复核确认以下核心缺陷：
1. **R1-A1【P0 缺陷】服务删除能力完全缺失**：
   - 后端路由 `pkg/microservice/aslan/core/service/handler/router.go:56`（`k8s.DELETE("/:name/:type", DeleteServiceTemplate)`）已完整具备删除能力；
   - 新前端 `api/service.ts` 未封装 `deleteService`，`pages/Services/` 没有任何删除服务按钮或入口，用户无法移除废弃服务，CRUD 严重不闭环。
2. **R1-A4【P1 缺陷】代码库/模板导入 API 模式性静默吞错**：
   - `service.ts` 中 `getCodehostNamespaces`、`getCodehostRepos`、`getCodehostBranches`、`getYamlTemplates`、`getYamlTemplateDetail` 5 处滥用 `catch { return [] }`，代码源或模板故障时页面显示假空下拉。
3. **R1-A5【P1 缺陷】服务详情与版本历史错误通道缺失**：
   - `loadServiceDetail` 与 `loadVersions` 失败时仅清空状态，无错误提示。
4. **R1-A2【P1 缺陷】服务标签 API 全未接线**：
   - `serviceApi.getServiceLabels`, `createServiceLabel`, `deleteServiceLabel` 存在于 API 层但 UI 零调用。

---

## 2. 修复实施核验

主控对 ZCode 提交的代码执行严格核验：
* **`deleteService` API 与删除交互完整闭环**：
  - 封装 `serviceApi.deleteService(serviceName, type, projectName, production)`；
  - 在服务列表行 Dropdown 菜单注入「删除服务」danger 项，在服务详情工具栏注入「删除服务」危险按钮；
  - 触发 `feedback.modal.confirm` 二次防误触弹窗，删除成功后提示并自动刷新列表与回退选中项。
* **API 吞错清理与导入弹窗错误反馈**：
  - 移除 5 处静默吞错，保留防御性响应解析；
  - 在 `ImportFromRepoModal.tsx` 与 `ImportFromTemplateModal.tsx` 补齐级联错误捕获与明确的 `message.error` 提示。
* **服务标签全套交互接线**：
  - 在服务编辑器上方新增服务标签 Tag 栏，动态渲染 `key: value` 标签并支持点击 `closable` 快捷删除；
  - 引入 Popover 快捷添加弹窗，联动系统标签注册表（`GET /api/aslan/system/labels`）选择标签键并保存。
