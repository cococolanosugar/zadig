## 一、审查背景与目标

作为十轮特战的最终决胜轮，本轮审查聚焦于企业级规范化资产管理的核心引擎——**模板中心（Templates Center）**。
模板中心承载着 Kubernetes YAML 模板、Helm Chart 模板、Dockerfile 模板、构建模板、代码扫描模板、工作流模板及发布计划模板七大资产类型，不仅涉及海量复杂配置与变量插值，更是后续微服务创建、工作流组装、镜像构建的基石蓝图。

经过深度比对后端路由与模型实现（`templatestore/handler/router.go`、`yaml.go`、`chart.go`、`dockerfile.go`、`build.go`、`scanning.go`、`workflow.go`），发现当前前端实现存在以下致命数据一致性与协议断层问题。

---

## 二、重大缺陷审计清单（Gaps & Protocol Misalignments）

### 1. 【P0 致命缺陷】YAML 与 Dockerfile 模板列表 Brief 结构导致编辑时数据覆盖清空
- **后端机制验证**：
  - 后端在 `pkg/microservice/aslan/core/templatestore/service/yaml.go` 与 `dockerfile.go` 中，列表接口（`ListYamlTemplate` / `ListDockerfileTemplate`）为了控制响应体积，返回的是极简的 `YamlListObject` 与 `DockerfileListObject`，其中**完全不包含 `Content` 字段**；
  - 完整的内容、变量定义 `VariableYaml` 与 `Variables` 仅存在于详情接口 `GET /api/aslan/template/yaml/:id` 与 `GET /api/aslan/template/dockerfile/:id` 中。
- **现存前端表现**：
  - 前端原实现直接从列表数据 `r.content` 注入编辑表单 `openEditTemplate('yaml', r.id, r.name, r.content)`；
  - 由于列表项没有 `content`，编辑模态框弹开时，YAML 与 Dockerfile 内容区呈现全白；
  - 用户一旦修改模板名称并点击保存，原有的宝贵模板脚本被完全覆盖为空字符串！导致生产资产损毁！
- **整改方案**：
  - 在 `templateCrudApi` 中补齐 `getYamlTemplate(id)` 与 `getDockerfileTemplate(id)`；
  - `openEditTemplate` 时，对所有已有模板（含 yaml、dockerfile、build、scanning、chart）统一开启 `detailLoading` 异步拉取真实详情后精准回填。

### 2. 【P0 协议破坏】Chart 模板变量配置数据协议严重 mismatch
- **后端机制验证**：
  - 后端路由 `PUT /api/aslan/template/charts/:name/variables`（`handler/chart.go:198-224`）中明确要求：
    ```go
    args := make([]*commonmodels.Variable, 0)
    if err := c.ShouldBindJSON(&args); err != nil {
        ctx.RespErr = errors.ErrInvalidParam.AddErr(err)
        return
    }
    ```
    请求体必须为一个 JSON 数组 `[{ key: string, value: string }]`；且提交的 key 集合必须与文件内已提取的变量 key 严格一致。
  - 获取接口 `GET /api/aslan/template/charts/:name/variables` 返回的也是 `ChartVariable` 数组。
- **现存前端表现**：
  - 前端原实现将变量接口误认为单行 YAML 文本框（`setChartVarsContent(content)`），并在保存时发送 `{ content: chartVarsContent }`；
  - 后端接收到非数组 JSON 后，直接报 HTTP 400 `ErrInvalidParam`，保存永远失败！
- **整改方案**：
  - 将 Chart 模板变量配置抽屉升级为结构化表格编辑：
    - 表格列展示变量 Key、可编辑 Value 输入框与描述；
    - 保存时组装标准的 `Array<{ key: string; value: string }>` 并通过修正后的 `saveChartTemplateVariables` 发送给后端；
    - 空变量时展示明确引导 Empty。

### 3. 【P1 体验断层】「查看内容」抽屉异步拉取与覆盖全部 4 大脚本型模板
- **现状**：
  - 点击列表「查看内容」因列表无 `content` 展现为“（无内容）”；构建模板与扫描模板无查看内容入口；
- **整改方案**：
  - `openViewContent(kind, id, name)`：统一开启 Loading 并在打开时异步请求对应详情接口（`getYamlTemplate` / `getDockerfileTemplate` / `getBuildTemplate` / `getScanningTemplate`），支持代码语法展示与变量列表；
  - 在构建模板与扫描模板表格操作列增加「查看内容」按钮。

### 4. 【P1 能力补全】工作流模板中心支持非内置模板删除
- **后端机制验证**：
  - 后端 `handler/router.go:97` 提供了 `workflow.DELETE("/:id", DeleteWorkflowTemplateByID)`；
- **整改方案**：
  - 在 `templateCrudApi` 补充 `deleteWorkflowTemplate(id: string)`；
  - 在工作流卡片底部，若 `!item.build_in`，增加 Popconfirm 删除按钮并与列表局部刷新联动。

## 三、任务拆解与 Cursor 落地指令

1. **`frontend/src/api/template.ts`**：
   - 补齐 `getYamlTemplate(id)`、`getDockerfileTemplate(id)`、`deleteWorkflowTemplate(id)`；
   - 修正 `saveChartTemplateVariables(chartName, payload: Array<{ key: string; value: string }>)` 的入参类型；
2. **`frontend/src/pages/Templates/index.tsx`**：
   - 重构 `openEditTemplate`：所有类型均通过接口拉取最新详情并回填；
   - 重构 `viewing` 抽屉：支持异步获取详情内容，覆盖 YAML、Dockerfile、构建脚本与扫描配置；
   - 重构 `chartVars` 抽屉：以结构化 Key-Value 表格形式编辑各变量值，并提交标准数组；
   - 工作流卡片增加非内置模板删除操作。
