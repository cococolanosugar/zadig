## 2. 专项复核详情

### 专项一：TriggerPanel 补齐 Jira 与 Meego 触发器 UI（P1-W1）
* **Tabs 扩展**：`TriggerPanel.tsx` 抽屉中的 Tabs 从原先 3 个扩展为 5 个，补齐 `jira` (Jira Webhook) 与 `meego` (飞书项目 Webhook)；
* **Jira Webhook**：
  * 支持列表展示：名称、Jira 项目 Key/集成 ID、监听事件 Tag（`enabled_issue_status_change` 时展示 `from_status → to_status`）、启用 Switch、删除 Popconfirm 二次确认；
  * 新建 Modal：包含名称、Jira 项目 Key、描述、状态变更监听开关与 from/to 状态输入，保存时通过 preset 预取 workflow_arg 并调用 `workflowApi.addJiraHook`；
* **Meego (飞书项目) Webhook**：
  * 支持列表展示：名称、飞书项目 Token/Key、描述、启用 Switch、删除 Popconfirm；
  * 新建 Modal：包含名称、飞书项目 Token/Key、描述、开启状态；保存调用 `workflowApi.addLarkHook`（走 `meegohook` 路由）；
  * **主控确认之契约对齐**：经查 `pkg/microservice/aslan/core/common/repository/models/workflow_v4.go:1817-1825`，后端 `MeegoHook` 结构体中无 `workitem_type` json 字段，表单中未盲目添加冗余死字段，并在 Modal 内以 `Alert` 提示由服务端集成配置统一回调，符合契约真相。

### 专项二：API 层模式性静默吞错清理与异常上抛（P1-E1）
* **吞错清理**：
  * `workflow.ts`：移除 `getWorkflows`、`getWorkflowTasks`、`listGeneralHooks`、`getJobEvents` 4 处的静默 `catch { return []; }`；
  * `settings.ts`：移除 22 处静默吞错，让配置列表在 HTTP 故障时正常上抛；
  * `rbac.ts`：移除 `listRoles`、`listRoleBindings`、`getResourceActions`、`listRoleTemplates` 4 处吞错；
  * `project.ts`：移除 2 处吞错；
* **契约防御性解析**：
  * 成功响应中完整保留 `Array.isArray(res) ? res : []` 防御性解析，仅网络或 HTTP 故障向上抛出；
  * 降级链保留：`getRegistries`、`getStorages`、`getProjects` 中的主通道与降级通道链完整保留，并在双通道均失败时抛出首个主异常；
  * 特性探测：`checkJenkinsExist` 与 `checkLLMIntegration` 保持语义化默认值探测并完善注释。
* **调用方兜底增强**：
  * 主控复核了 ZCode 识别并加固的 4 处裸调用（`RBAC.tsx` 裸 await、`WorkspaceBrowserDrawer`、`JobConfigDrawer`、`Execution.tsx`），保证接口抛错时界面展示 `feedback.message.error` 且不崩溃控制台。

### 专项三：SSE 日志流指数退避自动重连（P1-S1）
* **接口扩展**：`SSEOptions<T>` 增加 `autoReconnect?: boolean`（默认 true）、`maxRetries?: number`（默认 5 次）、`retryDelayMs?: number`（默认 1000ms），保持对已有 6 处调用 100% 向后兼容；
* **重连退避**：在流非主动 abort 中断时，按 1s → 2s → 4s → 8s 指数递增，10s 封顶；连接建立且接收到首包时重置计数；超过最大重试次数上抛 `onError`；
* **清理安全性**：返回的清理函数设置最高优先级 `isDestroyed = true`，同步调用 `clearTimeout` 清除定时器并执行 `controller.abort()`，彻底杜绝组件卸载后的内存泄漏与无效网络重连。

### 专项四：移动端测试与环境深链动态参数重定向（P1-R1）
* **重定向组件**：新增 `MobileTestDetailRedirect` 与 `MobileEnvDetailRedirect`，使用 `useParams` 提取参数；
* **路由映射**：
  * `/mobile/projects/detail/:projectName/tests` 与 `/tests/:testName` 动态跳转至桌面测试详情；
  * `/mobile/projects/detail/:projectName/envs` 与 `/envs/detail/:envName` 动态跳转至桌面环境；
  * **主控确认之路由对齐**：环境目标精确对齐 `envs/:envName`（与 `EnvironmentsPage` 的 `routeEnvName` 强绑定），避免字面量 `envs/detail/:envName` 错误命中 `ServiceDetailPage`。
