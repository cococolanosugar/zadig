## R1-A1【P0 闭环】服务删除 API 与界面删除交互

### `frontend/src/api/service.ts`
- 新增 `deleteService(serviceName, type='k8s', projectName='', production=false)`：`DELETE /api/aslan/service/services/:name/:type?projectName=&production=`，与规范书签名逐字一致；后端对照 `pkg/microservice/aslan/core/service/handler/router.go:56`（`k8s.DELETE("/:name/:type", DeleteServiceTemplate)`，query 参数经 handler `service.go` `c.Query("projectName")`/`production` 核实）。

### `frontend/src/pages/Services/index.tsx`
- **列表项操作菜单**：每个服务行新增 `MoreOutlined` Dropdown（click 触发，`stopPropagation` 防止误选行），含「删除服务」danger 项；
- **详情工具栏**：在「浏览代码库」与「保存配置」之间新增 danger「删除服务」按钮（`disabled={!selectedService}`），与同步/导入操作平级；
- **二次确认**：`feedback.modal.confirm`，文案严格按规范书：`确定删除服务 [${serviceName}] 吗？删除后该服务的 YAML 配置与组件将被移除。`，确认按钮 danger（"删除服务"）；
- **删除后闭环**：调 `serviceApi.deleteService` → `feedback.message.success('服务已成功删除')` → 若删除的是当前选中服务则清空编辑区/详情/标签状态 → `loadServices()` 刷新列表（自动回落选中首个服务）；失败透出后端 `response.data.message`。
- 服务类型自动解析：优先取 `serviceDetail.type`，回退列表项 `type`，最终回退 `'k8s'`，确保 Helm/PM 服务按正确类型删除。
