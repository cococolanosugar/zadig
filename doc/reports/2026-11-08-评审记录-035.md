## 1. 缺陷复核与修复确认

在 Cursor 提交的「项目创建 → 应用创建 → 环境创建 → 打包 → 编译 → 工作流 → 到审批 → 发布到目标 k8s」端到端黄金交付主链路穿透性审查报告中，主控独立复核确证并合入了以下关键问题：

1. **【P0 确证并修复】项目创建接口契约缺失与静默吞错治理**：
   - 文件：`frontend/src/api/project.ts`、`frontend/src/pages/Projects/index.tsx`
   - 问题：后端 API `/api/aslan/project/products` 强制校验 `product_name` 与 `product_feature` 字段，前端列表弹窗此前仅传递 `project_name`，必然触发 400 契约错误；且 `handleCreate` 中仅有空 catch 块，静默失败无任何错误提示。
   - 修复：在 API 层统一补齐 `product_name`（同名映射）与 `product_feature` 缺省结构（`basic_facility: 'kubernetes'`, `deploy_type: 'k8s'`, `create_env_type: 'system'`）；在页面层透传 `deploy_type`，并在 catch 块中通过 `feedback.message.error` 真实透出后端错误信息。

2. **【P0 确证并修复】工作流手动触发后跳转深链缺失 `/v1` 前缀**：
   - 文件：`frontend/src/components/WorkflowDAG/WorkflowTriggerModal.tsx`
   - 问题：触发任务成功后，导航路径为 `/projects/detail/${projectName}/pipelines/custom/...`，缺少系统统一的 `/v1` 前缀，导致用户在触发后直接被根路由匹配至“诚实 404”页面。
   - 修复：将项目深链修正为 `/v1/projects/detail/${projectName}/pipelines/custom/${workflowName}/${taskId}`，确保触发后 100% 直达工作流执行看板。

3. **【P0 确证并修复】向导与自定义工作流部署 Job 镜像来源断链治理**：
   - 文件：`frontend/src/pages/Projects/Wizard.tsx`、`frontend/src/components/WorkflowDAG/JobConfigDrawer.tsx`
   - 问题：在引导向导与流水线编排中，`zadig-deploy` 节点未指定镜像来源与关联的构建 Job，导致上游构建产出的镜像无法自动流入部署步骤，无法发布到目标集群。
   - 修复：
     - 在 `Wizard.tsx` 中生成的部署 Job 注入 `source: 'fromjob'`、`job_name: 'build'`、`deploy_contents: ['image']`；
     - 在 `JobConfigDrawer.tsx` 中为 `zadig-deploy` 增加「镜像来源」配置（`fromjob` / `runtime`），并在 `fromjob` 模式下要求指定上游构建 Job 名称，表单提交时自动组装 `deploy_contents: ['image']`。

4. **【P1 确证并修复】构建配置补齐 Dockerfile、上下文与镜像仓库推送目标**：
   - 文件：`frontend/src/pages/Projects/Builds.tsx`
   - 问题：构建配置表单缺少 Dockerfile 路径、构建上下文路径以及目标镜像仓库（Registry）的选择，导致构建任务生成的镜像无法正确推送到指定的镜像仓库供集群拉取。
   - 修复：引入 `settingsApi.getRegistries()` 动态加载镜像仓库选项，在构建模态框中增加 `docker_file`（缺省 `./Dockerfile`）、`build_context`（缺省 `./`）与 `registry_id` 选择框，并在编辑查看时支持完整回填。

5. **【P1 确证并修复】工作流任务执行看板活跃状态自动轮询**：
   - 文件：`frontend/src/pages/Pipelines/Execution.tsx`
   - 问题：工作流任务在运行中 (`running`)、等待审批 (`wait_for_approval`) 或排队中 (`waiting`) 时，界面没有自动轮询机制，审批人员审批通过后或任务构建完成后界面状态不发生改变，用户必须手动刷新页面。
   - 修复：增加 3 秒定时轮询机制，仅当任务处于活跃/待审批状态时自动轮询刷新任务详情；一旦到达终态（`passed`, `failed`, `timeout`, `cancelled`, `reject`）立即停止轮询，兼顾实时性与网络开销。
