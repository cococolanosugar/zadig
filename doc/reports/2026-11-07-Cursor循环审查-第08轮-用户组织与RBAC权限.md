## 2. 缺陷清单

### P0

#### R8-A1 · Settings「RBAC 角色列表」调用无 `namespace`（A · P0）

- **位置**：`settings.ts:468-470` `GET /api/v1/policy/roles`（无 query）；`Users/index.tsx:448-449` Tab `request` 调用之
- **L3**：`permission/role.go` `ListRoles` — `namespace is empty` → `ErrInvalidParam`
- **影响**：系统设置角色 Tab **无法列出任何角色**；配合 ProTable `success: true` + 空数组，呈现「系统无角色」假空态
- **建议**：系统级角色应改走 `role-templates` 或明确 `namespace=*` / 产品约定命名空间；禁止无 namespace 调 `policy/roles`

#### R8-A2 · API Token 硬编码占位 + 成功路径假 fallback（A · P0 · 假操作）

- **位置**：`Profile/index.tsx:47`
  ```ts
  useState(... || 'zadig_mcp_sec_live_token')
  ```
  `:180-183`
  ```ts
  const newToken = res?.token || `zadig_token_${Date.now()}`;
  setApiToken(newToken);
  feedback.message.success('...已成功重新生成！');
  ```
- **L3**：`POST /api/v1/users/:uid/token` → `GenerateAPIToken`
- **影响**：未生成时展示伪 Token；响应字段缺失时仍提示成功并写入本地伪造串，可导致 MCP/API 调用静默鉴权失败
- **建议**：无真实 token 显示「未生成」；仅 `res.token` 存在时 success；缺字段走 error。Users 管理页若需代管 Token，单独入口且禁止 fallback

### P1

#### R8-A3 · 创建用户「系统初始角色」UI 未提交（A · P1 · 假操作）

- **位置**：`Users/index.tsx:370-378` 表单字段 `role`；`:97-105` `createUser` payload **不含** `role`
- **影响**：用户以为已赋 Admin/User，实际仅创建账号，权限依赖后续绑定 → 典型假操作
- **建议**：对接真实赋权契约（创建后 `role-bindings` 或后端 CreateUser 支持的字段）；或移除误导字段

#### R8-A4 · 用户更新 / 管理员重置密码 / 管理员 Reset MFA 缺失（A · P1）

| L3 | 前端 Users 页 | 备注 |
| --- | --- | --- |
| `PUT /users/:uid` | ❌ | 无编辑 |
| `PUT /users/:uid/password` | ❌ 管理端 | Profile 自助改密有（需 oldPassword） |
| `DELETE /users/:uid/mfa` | ❌ | Admin Reset；Profile 为用户自助 disable |
| `POST .../mfa/*` 管理视角 | ❌ | — |
| `POST /users/:uid/token` | ❌ Users 页 | 仅 Profile |

- **建议**：Users 行操作增加「编辑」「重置密码」「重置 MFA」；封装 `settingsApi.updateUser` / `resetUserPassword` / `resetUserMfa` / `generateUserToken`

#### R8-A5 · 项目角色无更新；角色模板 API 死代码（A · P1）

- **L3**：`PUT /policy/roles/:name`；`role-templates` CRUD
- **现状**：`rbac.ts` **无** `updateRole`；有完整 `list/get/create/update/deleteRoleTemplate` 但 `RBAC.tsx` **零引用**
- **UI**：仅创建 + 删除自定义角色；无基于模板一键创建
- **建议**：编辑角色 Drawer 调 PUT；创建流可选模板 `getRoleTemplate` 预填 actions；内置模板 `type===1` 禁止编辑删除（与项目角色 `type==='system'` 一致）

#### R8-A6 · RoleBinding 更新接口未封装；新增绑定失败静默（A · P1）

- **L3**：`POST /role-bindings/user/:uid`、`POST .../group/:gid` 更新绑定
- **前端**：仅 `createRoleBinding` + delete；改角色需删绑再建（无引导）
- **静默**：`RBAC.tsx:136-137` / `:168-169` `catch { return false }` **无** `message.error`（删除路径有 error，对比鲜明）
- **建议**：封装 update；表单失败统一 `feedback.message.error`

#### R8-A7 · 用户删除 / 创建失败吞错（A · P1）

| 位置 | 行为 |
| --- | --- |
| `Users/index.tsx:92-93` | `handleDeleteUser` `catch { // Handled }` |
| `:109-110` | `handleCreateUser` `catch { return false }` 无 error 文案 |
| `GroupMembersDrawer.tsx:69-70` | `loadData` Handled |
| `RBAC.tsx:107-109` | users/groups/actions `.catch(() => [])` |

- 用户组 CRUD、成员增删主路径反馈 **良好**（正向对照）

### P2

#### R8-A8 · `all-users` 组成员回退为全量用户列表（A · P2）

- `GroupMembersDrawer.tsx:62-64`：详情无 `uids` 且组名为 `all-users` 时，用 `getUsersBrief()` 全量填充 — 可能与后端真实成员不一致
- **建议**：严格依赖 `GET /user-group/:id`；失败 warning，勿合成

#### R8-A9 · `rbacApi` 多处 `skipErrorHandler: true` 依赖调用方（A · P2）

- 列表解析为空数组时易掩盖 401/403；RBAC 页列表已有 error，其它复用方需规范

#### R8-A10 · 危险操作确认总体良好（正向）

- 删用户/删组/移出成员/解绑/删角色均有 Popconfirm；系统组锁定文案有
- `rowKey`：用户 `uid`、绑定合成 key、角色 `name` — **未见** `Math.random()`
