## 1. 本轮审查与核心缺陷复核

本轮聚焦 **系统集成与代码源/凭据 (Integrations & Connectors)**，Cursor 独立审计出核心缺陷，主控复核确认：
1. **R5-A1【P0 致命反模式】集群缓存清理假成功止血**：
   - `ClusterCleanCacheModal.tsx:59-62` 原代码在 `catch` 块中将 progress 置 100%、设置 `cleaned=true` 并调用 `feedback.message.success` 假成功提示掩盖错误。
2. **R5-A2【P1 核心能力】CodeHost 连通性测试、更新与 OAuth 闭环**：
   - 后端路由 `codehost/handler/router.go` 提供 `validate`、`PATCH /:id`、`GET /:id/auth`；
   - 前端此前 API 层与 UI 层均缺少测试连接与更新能力。
3. **R5-A3【P1 核心能力】S3 / DBInstance / HelmRepo 连通测试与更新对齐**：
   - 后端明确提供了 `/validate` 与 `PUT /:id` 更新端点；
   - 此前前端 API 层缺少对应方法，页面仅提供「只能删建」的受限生命周期，表单无连通性测试。
4. **R5-A4【P1 缺陷】大面积模式性吞错与静默失败治理**：
   - `Storage`、`DBInstances`、`ChartRepos`、`CodeHosts`、`Registries`、`Clusters`、`KeyVault` 等页面均存在 `catch { // Handled }` 或 `catch { return false; }` 无错误反馈的问题。

## 2. 修复实施核验

主控对 ZCode 提交的代码执行逐项核验：
* **止血 R5-A1 集群缓存清理假成功**：
  - 移除 catch 中的 `setCleaned(true)` 与 success 消息，替换为 `setProgress(0)` 与 `feedback.message.error` 真实反馈错误。
* **补齐 settingsApi 基础设施接口 (R5-A2 / R5-A3)**：
  - CodeHost：增加 `validateCodeHost`、`updateCodeHost`、`authCodeHost`；
  - S3 Storage：增加 `validateStorage`、`updateStorage`；
  - DBInstance：增加 `validateDBInstance`、`updateDBInstance`；
  - HelmRepo：增加 `updateHelmRepo`，将 `validateHelmRepo` 接入跳过拦截器模式。
* **接入连通性测试交互与操作增强 (R5-A3)**：
  - `CodeHosts` 新增表单接入 `<Button key="test-conn" icon={<ApiOutlined />} ...>` 调用 `validateCodeHost`；
  - `Storage` 新增表单接入「测试连接」调用 `validateStorage`，行列表增加「设为默认」按钮调用 `updateStorage`；
  - `DBInstances` 新增表单接入「测试连接」调用 `validateDBInstance`；
  - `ChartRepos` 新增表单接入「测试连接」调用 `validateHelmRepo`。
* **全量吞错治理 (R5-A4)**：
  - 对 7 大设置页面（Storage、DBInstances、ChartRepos、CodeHosts、Registries、Clusters、KeyVault）所有 CRUD catch 块统一注入 `feedback.message.error(msg)`，彻底杜绝静默失败。
