## 1. 本轮审查与核心缺陷复核

本轮聚焦 **发布计划与版本交付 (Release Plan & Delivery)**，Cursor 独立审计出 10 项缺陷，主控复核确认并制定修复规范书：
1. **R4-A3【P0 致命反模式】Delivery 批量部署幻觉路由与 catch 假成功**：
   - `Delivery/index.tsx` 原代码在 `handleBatchDeploy` 中调用不存在的 `/releases/:id/deploy` 路由，且在 `catch` 块中调用 `message.success` 伪造成功提示掩盖网络或 404 错误。
2. **R4-A1 & R4-A2【P0 核心能力缺失】发布计划执行/审批/重试/复制控制面缺失，抽屉内硬编码假数据**：
   - 后端 `release_plan/handler/router.go` 提供丰富的计划执行管控接口（`execute`, `retry`, `skip`, `approve`, `copy`, `logs`）；
   - 前端抽屉此前硬编码了假的 4 步里程碑静态数组，缺失真实 Job 编排面板、审批流与执行控制。
3. **R4-A6【P1 缺陷】`releasePlanApi.getPlans()` 模式性吞错**：
   - 原代码 `catch { return []; }` 导致在网络错误或权限不足时静默展示空数据，阻断错误定位。
4. **R4-A7 & R4-A8【P1 缺陷】交付中心版本删除 UI 缺失与 Retry 下沉**：
   - `deleteDeliveryVersion` 已有后端实现但前端列表缺少操作入口；`retryDeliveryVersion` 页面直调未下沉至 API 层。
5. **R4-A9【P2 缺陷】Delivery 列表与详情静默 catch 吞错**：
   - `fetchData`、`handleViewDetail`、`handleBatchDeploy` 等方法补齐错误提示。

## 2. 修复实施核验

主控对 ZCode 提交的代码执行逐项核验：
* **止血 R4-A3 批量部署假成功**：
  - 移除 catch 伪造的 success 消息，替换为 `feedback.message.error` 真实反馈错误，防止生产操作误判。
* **补齐 releasePlanApi 核心管控接口 (R4-A1)**：
  - 移除 `getPlans()` 的静默吞错；
  - 增加 `getPlan(id)`、`copyPlan(id, name)`、`executeJob(id, jobArgs)`、`retryJob(id, jobArgs)`、`skipJob(id, jobArgs)`、`approvePlan(id, comment)`、`getPlanLogs(id)`。
* **接入真实 Job 编排执行面板 (R4-A2)**：
  - 移除原假里程碑写死 DOM；
  - 引入真实 Job 表格（名称、类型、状态、负责人、操作执行/重试/跳过）；
  - 引入审批流动作条（待审批状态支持一键审批通过并刷新）；
  - 增加复制计划 Modal 与操作日志 Timeline Drawer。
* **交付中心版本删除与重试对齐 (R4-A7 / R4-A8)**：
  - 在 `deliveryApi` 下沉 `retryDeliveryVersion` 与 `getArtifactByImage`；
  - 在版本列表操作列增加带有危险提示 Popconfirm 的「删除版本」按钮，闭环调用 `deleteDeliveryVersion`。
* **全局错误提示补齐 (R4-A9)**：
  - 交付中心与发布计划页面各请求 catch 块统一接入 `feedback.message.error`。
