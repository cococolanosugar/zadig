## 一、审查与修复背景

在第 10 轮针对「模板中心（Templates）」的闭环审查中，深度比对了 Kubernetes YAML 模板、Helm Chart 模板、Dockerfile 模板、构建模板、代码扫描模板、工作流模板与发布计划模板的全生命周期操作。发现原前端存在以下致命隐患与协议破坏：
1. **列表 Brief 结构导致编辑时数据覆盖清空**：后端的 `ListYamlTemplate` 和 `ListDockerfileTemplate` 仅返回极简的 `YamlListObject` 与 `DockerfileListObject`（无 `content` 字段），前端原先直接从列表取 `content` 回填编辑表单，导致打开时全白，一旦保存便将原有生产资产清空覆写；
2. **Chart 模板变量配置协议严重 mismatch**：后端 `PUT /api/aslan/template/charts/:name/variables` 强制要求请求体为 `Array<{ key: string, value: string }>`，原前端将其作为单文本框传递 `{ content: ... }`，直接触发 HTTP 400 `ErrInvalidParam`；
3. **查看内容抽屉因列表无 `content` 展现空白**，且构建模板与扫描模板缺失查看入口；
4. **工作流模板缺少非内置模板的删除操作**。

---

## 二、修复落地核验

### 1. 强类型 API 补全 (`frontend/src/api/template.ts`)
- 补充 `templateCrudApi.getYamlTemplate(id)`：调用 `GET /api/aslan/template/yaml/:id` 获取包含 `content` 与 `variables` 的完整 `YamlDetail`；
- 补充 `templateCrudApi.getDockerfileTemplate(id)`：调用 `GET /api/aslan/template/dockerfile/:id` 获取包含 `content` 的 `DockerfileDetail`；
- 补充 `templateCrudApi.deleteWorkflowTemplate(id, force)`：调用 `DELETE /api/aslan/template/workflow/:id`；
- 修正 `templateApi.saveChartTemplateVariables` 参数签名：强类型约束入参为 `Array<{ key: string; value: string }>`。

### 2. 页面与交互全面闭环 (`frontend/src/pages/Templates/index.tsx`)
- **全异步详情回填编辑 (`openEditTemplate`)**：
  - 针对 `yaml`、`dockerfile`、`chart`、`build`、`scanning` 5 类模板，只要编辑已有模板，统一开启 `detailLoading` 异步拉取真实详情，并精准回填，彻底杜绝空白覆盖清空风险；
  - YAML 模板在回填后自动执行变量提取与标签展示；
- **结构化 Chart 变量配置抽屉 (`chartVars`)**：
  - 彻底废弃纯文本 TextArea，升级为标准的 Key-Value 可编辑表格；
  - 每一行展示变量 Key、可编辑 Value 输入框与描述说明；
  - 保存时组装标准的 `Array<{ key: string; value: string }>` 并严格按后端协议提交；
  - 变量为空时提供标准 Empty 占位；
- **通用异步详情查看抽屉 (`openViewContent`)**：
  - 统一异步拉取并展示 YAML、Dockerfile、构建脚本与扫描配置的格式化内容；
  - 在构建模板操作列增加「查看脚本」，在扫描模板操作列增加「查看配置」；
- **工作流非内置模板删除闭环**：
  - 在工作流卡片底部，若 `!item.build_in`，增加 Popconfirm 危险删除操作，并与本地卡片列表刷新联动。
