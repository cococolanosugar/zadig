## 1. 审查背景与对账结论

本轮对工作流 V4 引擎的四条深度链路（插件 Job、矩阵/多环境并发、执行状态机、断点调试）做"模型结构体 → 前端消费点"逐字段对账。

**对账总判定**：
- **发现 1 项 A 类契约断裂（LOOP3-A1 插件 Job 配置表单缺失）**：用户可在画布添加 plugin Job 节点，但配置抽屉零渲染，保存的 spec 缺 `plugin` 字段 → 执行必失败；
- **发现 1 项 B 类（LOOP3-B1 Job 高级设置零接线）**：`JobAdvancedSettings`（超时/集群/资源规格/调度策略/任务标签/共享存储）在 JobConfigDrawer 零 wiring；
- 状态机（approve/pause-manualexec/retry/clone/cancel）与断点调试（breakpoint/debug/podexec WS）两条链路**全部对齐**；
- 规范书"Matrix Job"在本地后端无对应概念（多环境并发由 stage parallel + env_options 承载），"job 级 skip"在 V4 任务无独立端点 —— 均为口径澄清（C 类）。

## 2. 四大穿透核查点结论

### 审查点 1：自定义插件 Job 契约与动态参数渲染 — 🔴 A 类断裂

**后端契约（完整建模）**：
- plugin 组 5 端点齐备（router.go:171-177）：`GET /template`、`GET|POST /plugin`、`POST /enterprise`、`DELETE /:id`；
- `PluginJobSpec{plugin: PluginTemplate, advanced_setting}`（models/workflow_v4.go:424-428）；
- `PluginTemplate`（plugin_repo.go:40-53）含 **inputs/outputs 动态参数**、args/cmds/envs、version（版本选择）、category 等完整字段 —— 动态参数渲染的数据源齐备。

**前端现状（断裂点）**：
1. `WorkflowCanvas.tsx:340` 新建 Job 下拉**提供** `插件任务 (plugin)` 选项；
2. `JobConfigDrawer.tsx` **零 plugin 分支**（全文件无 `'plugin'` 字符串）——用户添加 plugin Job 后打开配置抽屉无任何可配置项，`handleFinish` 组装的 spec 无 `plugin` 字段；
3. `workflowApi.listPluginTemplates/listPluginRepositories`（:1132/:1141）**仅被 Settings/Config 插件仓库管理消费**（:327/:776），编排器未消费；
4. 后果：用户添加 plugin Job 节点 → 保存 → spec.plugin 为空 → 工作流执行该 Job 必失败（后端无法解析插件）。

**修复方案（LOOP3-A1）**：
```ts
// JobConfigDrawer.tsx 新增 plugin 分支：
// 1) useEffect job.type==='plugin' 时调用 workflowApi.listPluginTemplates() 填充插件下拉（label=name+version，按 category 分组）
// 2) 选中插件后按 template.inputs 动态渲染参数表单（Param: name/description/type/default → Input/Select），
//    outputs 只读展示（供下游 Job 引用输出变量）
// 3) handleFinish 组装：spec: { plugin: selectedTemplate, ...values.inputs 映射为 params }
// 4) 回填：job.spec.plugin 驱动选中态
```

### 审查点 2：多环境/矩阵构建触发契约 — ✅ 主链对齐（1 项 B 类 + 口径澄清）

**口径澄清（C 类）**：本地后端**无 Matrix Job 概念**（`pkg/microservice/aslan/core/workflow` 全量 grep `matrix|Matrix` 零命中）。多环境并发承载方式为：stage 级 `parallel` + deploy job 的 `env_options`（`ZadigDeployEnvInformation{env, env_alias, production, registry_id, services[]}`，models:974-980，执行时动态勾选服务与目标环境）。

**前端对账**：
- 执行时动态勾选 ✓：`WorkflowTriggerModal.renderDynamicVar`（:48-56）调用 `renderDynamicVariables` 按 preset 动态渲染参数（含 env_options 驱动的服务/环境勾选），与后端 Handler 的 preset 渲染契约对齐；
- 配置时环境/服务动态加载 ✓：JobConfigDrawer 按类型拉取 environments/services（:304-323）。

**LOOP3-B1（JobAdvancedSettings 高级设置零接线）**：后端 `JobAdvancedSettings`（models:1691-1713）建模完整——timeout、cluster_id/cluster_source、res_req/res_req_spec 资源规格、strategy_id 调度策略、custom_annotations/custom_labels 任务标签与注解、share_storage_info/storages 共享存储。前端 JobConfigDrawer **全文件无 `advanced_setting` 组装或表单**（grep 零命中），用户无法在 UI 配置任何高级项（集群选择退化为默认、资源规格不可调、调度策略不可选）。**建议**：JobConfigDrawer 增加「高级设置」折叠面板，按 job 类型消费 `advanced_setting`（至少覆盖 cluster_id + res_req + timeout 三项高频字段，`handleFinish` 组装 `spec.advanced_setting`）。

## 4. 总结

1. **执行状态机与断点调试两条链路完全对齐**（approve/pause-manualexec/retry/clone/cancel/breakpoint/debug/podexec 八项逐字段核验通过），前两轮（R2 修复、R12 轮询）的成果经本轮复验保持生效；
2. **唯一 A 类为插件 Job 配置表单缺失**——数据模型与仓库管理 API 均已就绪，缺的仅是编排器内一块动态表单，修复路径清晰（约 120 行，含插件下拉 + inputs 动态渲染 + spec 组装）；
3. `JobAdvancedSettings` 零接线为次优先 B 类（不阻断执行，但高级调度能力不可配置），可与 A1 同抽屉分期交付；
4. Matrix Job / job 级 skip 为规范书口径与本地后端实现的差异，非前端缺陷，已澄清并记录。
