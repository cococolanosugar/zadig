## 2. A 类真实缺陷清单

### P0

本轮**未发现**操作失败仍 `message.success` 的假成功 P0（看板保存/删除、AI 真实分析失败均有错误通道）。

### P1

#### R7-A1 · AI 效能雷达与关联 v2/ai 接口全未接线（A · P1）

| L3（`router.go:79-87`） | `stat.ts` | Insights UI |
| --- | --- | --- |
| `GET /v2/ai/radar` | ❌ | ❌ |
| `GET /v2/ai/attention` | ❌ | ❌ |
| `GET /v2/ai/overview` | ❌ | ❌ |
| `GET /v2/ai/build/trend` | ❌ | ❌ |
| `GET /v2/ai/requirement/period` | ❌ | ❌ |
| `POST /v2/ai/analysis` | ✅ `getAiAnalysis` | ✅ AiAnalysisDrawer |
| `GET /v2/ai/analysis/prompt` | ✅ | ✅ |

- **影响**：规范要求的「AI 效能雷达与效能分析」仅完成对话分析半边；雷达/关注/需求周期等可视化与 EE 能力不对齐
- **建议**：在 `stat.ts` 封装上述 GET；Insights 总览或 Detail 增加雷达图 / 月度关注卡片 / 近 30 日构建趋势（可复用 `build/trend`）

#### R7-A2 · 看板外源指标缺少 `api_config` 配置面（A · P1）

- **L3 / 类型**：`StatDashboardConfig.api_config`（`external_system_id` / `api_path` / `queries`）见 `stat.ts:100-104`
- **UI**：`Insights/index.tsx:987-993` 可选 `source=external`，但 Modal **无** api_config 字段；保存 payload（`:309-316`）不提交外源配置
- **影响**：外部系统指标无法按契约持久化，选 external 实际无效
- **建议**：`source===external` 时展开外源系统选择与 path/queries；校验必填后写入 payload

#### R7-A3 · Insights 主加载静默吞错（A · P1）

| 位置 | 行为 |
| --- | --- |
| `Insights/index.tsx:225-226` | `fetchInsightData` `catch { // Handled }` — KPI/图表失败无提示 |
| `:236-237` | configs 失败 → `[]` |
| `:258-259` | `fetchDashboardV2` `catch { // Handled }` |
| `Detail.tsx:126-171` | 各维度 `.catch(() => setXxx空)` — 无 `message` |
| `AiAnalysisDrawer.tsx:113-114` | prompts 失败静默回落本地默认（可接受，建议 warning） |

- **对照**：`Statistics/index.tsx:97-98` 已有 `feedback.message.error`（正向范例）
- **建议**：Promise.allSettled 若全部 rejected 或关键请求失败 → `message.error`；部分失败可 warning + Empty

#### R7-A4 · `statApi` v2/quality 大片死代码（Insights/Statistics 未消费）（A · P1/P2）

已封装但本轮三页（及 Insights 关联）**零引用**（仅定义于 `stat.ts`）：

- `getDeployHealthStats` / `getDeployWeeklyTrend` / `getDeployMonthlyTrend`
- `getTopDeployedServices` / `getTopDeployFailures`
- `getRollbackTotalStat` / `getTopRollbackedServices` / `getRollbackWeeklyTrend`
- `getRecentTestTasks` / `getDailyTestHealthTrend`（Quality 页另有直连 dailyHealth，非 Insights）

Detail 部署/测试主要靠 `dashboard/*` + 旧 `quality/*` POST + `rollback/stat`，与 v2 quality GET 族重复且未统一。

- **建议**：Detail「部署/回滚」Tab 改接或并列 v2 trend/top；或删除未用封装避免契约漂移幻觉

#### R7-A5 · AI「查看模拟分析效果」硬编码报告（A · P1 · 假数据入口）

- **位置**：`AiAnalysisDrawer.tsx:50+` `MOCK_AI_REPORT`；`:181-190` `handleApplyMockReport` → `message.success('已展示模拟效能分析报告')`
- **性质**：用户主动点击（非 catch 假成功），但产出**非后端契约数据**，易与真实 LLM 回答混淆
- **建议**：模拟内容加显著「模拟」Tag；生产构建可隐藏或仅 `import.meta.env.DEV` 启用

### P2

#### R7-A6 · 时间跨度缺少 14 天与自定义区间（A · P2）

- 规范提及 7/14/30/自定义；实现仅 **`7d | 30d | 90d`**（`Insights/index.tsx:130`、`Detail.tsx:106`）
- 传参单位正确：`Math.floor(Date.now()/1000)` + 天×86400 → **unix 秒**；AI `start_time/end_time` 同为秒（`:137-142`）
- **建议**：补 14d；可选 `RangePicker` 映射秒级 `startDate/endDate`

#### R7-A7 · AI 分析窗口固定近 30 天，未跟随页面 timeRange（A · P2）

- Drawer 内写死 `now - 30 * 86400`，与大盘 7/90 日切换脱节
- **建议**：props 传入 Insights 当前 `timeRange` 起止

#### R7-A8 · Statistics 页能力面偏窄（A · P2）

- 仅 `dashboard/overview` + 近 7 日 build + 集群列表；无 release/test KPI、无 v2 general
- 空态/错误通道相对健康；属产品切片不足而非假数据

#### R7-A9 · 看板与项目绑定切换弱（A · P2）

- v2 dashboard 按全局时间拉多项目评分表，**无**显式多项目多选过滤 UI；依赖后端返回全集
- Overview KPI 的服务数仅在 `currentProject` 有值时拉服务列表
