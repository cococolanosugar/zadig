**对账总判定**：

## 2. 发现的真实缺口

### LOOP1-A1（P0 · 数据源断裂）服务主 YAML 编辑器从未获得真实 YAML 内容

**证据链**：
1. 列表接口 `GET /api/aslan/service/services` 的响应结构为 `commonservice.ServiceProductMap`（`pkg/microservice/aslan/core/common/service/service.go:114-137`），字段仅含 `service_name/source/type/containers/codehost/estimated_merged_variable*` 等 —— **不含 `yaml` 字段**；
2. 但前端 `pages/Services/index.tsx` 在 `loadServices`（:203 `setYamlContent(chosen.yaml || '')`）与服务行点击（:827 `setYamlContent(item.yaml || '')`）均以 **`item.yaml`（恒为 undefined）** 填充编辑器与 `originalYaml`；
3. `loadServiceDetail`（:225-236）拉取的 `getServiceDetail` 响应**包含 `detail.yaml`**，但该函数仅 `setServiceDetail(detail)`，**从未回填 `yamlContent`**（全文件 8 处 `setYamlContent` 调用点无一来自 detail）；
4. 编辑器绑定 `value={yamlContent}`（:1016）。

**后果**：选中任意服务后主编辑器为空白；此时若点击「保存配置」（`POST services?force=true`，body `yaml: yamlContent`，:393/:431），将以**空 YAML 覆盖服务配置**——属数据破坏级风险。向导新建的服务因创建时本地 `setYamlContent(defaultYaml)` 短暂可见，切页后同样丢失。

**修复方案（供 Cursor 实施）**：
```ts
// loadServiceDetail 成功分支（detail 拉取后）回填编辑器：
const detail = await serviceApi.getServiceDetail(...);
setServiceDetail(detail);
setYamlContent(detail.yaml || '');
setOriginalYaml(detail.yaml || '');
setIsDiffMode(false);
```
同时删除 `loadServices` 与列表行点击中的 `setYamlContent(item.yaml || '')`（列表无该字段，避免误导），改由 detail 统一供源；列表行点击仅 `setSelectedService`（detail effect 会自动联动）。

### LOOP1-A2（P1 · 回滚刷新链断裂）回滚成功后编辑器与详情不刷新、选中上下文丢失

**证据链**：
1. `handleRollback`（:512-526）成功后仅 `await loadServices()`；
2. `loadServices` 的选中逻辑 `chosen = (queryServiceName && ...) || list[0]`（:198）**不保留当前 `selectedService`**——回滚非首位服务时选中被重置、编辑器内容跳变；
3. 即便服务名恰好不变，`useEffect [selectedService]`（:240-245）因 React 同值不重跑，`serviceDetail`（variable_yaml/service_variable_kvs/containers/codehost_id）保持回滚前旧数据 → 「变量配置」抽屉、「从代码库/模板同步」按钮基于陈旧详情；
4. 回滚接口本身参数契约与后端对齐（`POST /services/version/:name/rollback?projectName=&production=&revision=`，handler version.go 校验 projectKey/production）✓。

**修复方案**：`handleRollback` 成功分支改为：
```ts
feedback.message.success(`服务已回滚至版本 ${revision}`);
await loadServiceDetail(selectedService);   // 重拉详情（含回滚后 yaml）
setIsDiffMode(false);
setVersionYaml(null);                        // 关闭已打开的旧版本预览
// 不调用 loadServices()（列表字段不随回滚变化），或如需刷新列表须保留当前选中：
// await loadServices(); setSelectedService(selectedService);
```

### LOOP1-C1（C 类 · 高阶体验）手工构建模块容器名无下拉来源

- 多容器**主链完好**：YAML 保存后由服务端解析，`ServiceModulesDrawer` 的 auto-modules 列表（`GET /services/auto-modules`）实时呈现容器映射；
- `ServiceDetail.containers`（api/service.ts:29，字段 `{name,image,image_name}`）已在类型层声明且详情接口返回，但**无任何 UI 消费**；
- 手工模块创建/编辑表单的 `name`（容器名）为自由文本，用户需自行翻 YAML 猜容器名。
- **增强建议**：将手动模块表单 `name` 升级为 Select，选项来自父页传入的 `serviceDetail.containers[].name`（多容器服务自动去重）；单容器服务保持 Input。

### LOOP1-C2（C 类）版本 YAML 预览失败静默

`handleViewRevision`（:499-510）catch 仅置空，无用户反馈；对比同页 `loadVersions` 已有错误提示。建议补 `feedback.message.error('版本 YAML 获取失败')`。

## 3. 其余两审查点结论（无 A 类缺口）

### 审查点 3：服务模板关联与级联更新 — ✅ 闭环
- 模板创建链：`POST /template/yaml|dockerfile` 与 `loadServiceFromTemplate`（`service.ts:360`）均封装并接 UI；
- 级联更新链：已存在服务的同步走 `reloadServiceFromTemplate`（`service.ts:372`，`POST /template/reload`），由 Services 页「从模板同步」按钮（:534-550，仅 `serviceDetail.template_id` 存在时渲染）→ `ImportFromTemplateModal` 的 sync 分支触发，按钮事件绑定完整；
- 自动同步态（`auto_sync`）在列表/编辑表单均有呈现与禁用保护（配置编辑对 `auto_sync === true` 的 ConfigMap 禁改属环境域，服务域 autoSync 徽标展示正常）；
- 无空 catch、无未绑定事件。

### 审查点 4：项目向导多服务导入与错误处理 — ✅ 无 A 类
- 向导创建链 `failures[]` 汇总机制完整（服务/环境/工作流任一失败均收集并最终 `feedback.message.error` 汇报）；
- 从代码库批量导入交互集中在 Services 页 `ImportFromRepoModal`：预加载失败（:127-129）、仓库列表失败、分支列表失败均有 `message.error`；空预加载有 warning 提示；`getUsersBrief` 等支撑调用均带 `.catch` 降级（R16 已治理）；
- C 类增强建议（可选）：向导第 2 步（服务配置）可内嵌"从代码库导入"入口减少页面跳转，属产品演进非缺陷。
