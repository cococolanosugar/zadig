## 专项一：模板中心写能力与错误通道（P1-02 & P1-05）

### `frontend/src/api/template.ts`
- **错误通道修复**：7 个列表方法（workflow/yaml/dockerfile/charts/build/scanning/release_plan）移除静默 `catch { return [] }`，异常向上抛出由调用方呈现错误态（`res || fallback` 归一保留）。
- **写契约补齐**（`templateCrudApi` 新增 12 个方法，后端对照 `templatestore/handler/router.go:44-49,81-87,100-106`）：
  - Chart：`getChartTemplate(name)` / `createChartTemplate` / `updateChartTemplate(name,…)` / `deleteChartTemplate(name)`（payload 对齐 `addChartArgs`+`fs.DownloadFromSourceArgs`：`{name, codeHostID, owner, namespace?, repo, path, branch}`，注意后端 json tag 为 `codeHostID` 驼峰）
  - Build：`getBuildTemplate(id)` / `createBuildTemplate` / `updateBuildTemplate(id,…)` / `deleteBuildTemplate(id)`（payload=`BuildTemplate{name, scripts, timeout, pre_build}`；**`pre_build` 必带**——后端 `service/build.go:47` 无判空直接解引用，缺省将 panic）
  - Scanning：`getScanningTemplate(id)` / `createScanningTemplate` / `updateScanningTemplate(id,…)` / `deleteScanningTemplate(id)`（`AdvancedSetting` 后端已判空，可最小 payload）

### `frontend/src/pages/Templates/index.tsx`
- **页面级错误态**：新增 `listError` 状态；两个列表 useEffect 失败时展示 `Alert(title/description)` + 「重试」按钮（复用 `reloadActiveTabList`），不再以空表误导。
- **写交互落地**：`openCreateTemplate` 按 tab 分发（charts/builds/scanners 均可新建）；三个表格新增「操作」列（编辑/删除，删除带 Popconfirm）；编辑时先 `GET` 详情回填（Chart 锁定名称）。
- **编辑 Modal** 扩展四种表单：
  - Chart：代码源下拉（懒加载 `settingsApi.getCodeHosts()`，`/api/v1/codehosts`）+ owner/namespace/repo/branch/path；
  - Build：脚本 textarea + 超时分钟数（默认 600），保存 payload 固定携带 `pre_build:{res_req:'low'}`；
  - Scanning：scanner_type（sonar/other）+ enable_scanner 开关 + Sonar 参数 + 自定义脚本。

## 专项二：SAE 变更单与回滚抽屉（P0-02）

### `frontend/src/api/environment.ts`（+142 行）
- 新增 SAE 契约六项：`listSAEEnvs`、`listSAEApps`（选级辅助）+ 规范四项 **`listSAEChangeOrders` / `getSAEChangeOrderDetail` / `abortSAEChangeOrder` / `rollbackSAEChangeOrder`**。
- **契约修正说明**：spec 中的路径 `/api/aslan/environment/sae/:envName/app/:appID/...` 为缩写；实际后端挂载为 `environments` 组内 `sae/:name/app/:appID/...`（`environment/handler/router.go:242-245`，`c.Param("name")`），完整 URL 为 `/api/aslan/environment/environments/sae/:envName/app/:appID/changeOrder…`，query 携带 `projectName/production/page/per_page`（handler `environment.go:3585-3775` 逐参数核对）。已按真实契约实现。
- 响应为阿里云 SAE OpenAPI 透传（`converter.ConvertToSnakeCase`），类型定义做防御性可选字段。

### `frontend/src/pages/Environments/SAEChangeOrderDrawer.tsx`（新增，347 行）
- 层级选择：SAE 环境 → SAE 应用（单应用自动选中）→ 变更单表格。
- 表格列：变更单 ID/名称、变更类型（co_type）、状态 Tag（阿里云 0 准备/1 执行中/2 成功/3 失败 映射，含时间戳秒级兼容）、创建人、创建时间、操作（详情/中止变更/一键回滚）。
- 中止与回滚均经 `feedback.modal.confirm` 二次确认（danger 按钮），成功后自动刷新列表。
- 详情内嵌渲染：状态、描述、`descriptions` 标签组、`pipelines` 阶段表（透传字段防御性消费）。
- 错误通道：列表失败展示 Alert+重试（社区部署无 SAE License 时后端返回许可错误，原样呈现给用户）。

### `frontend/src/pages/Environments/index.tsx`
- 深链承接：`/sae/changeOrder*` 三条路由落在本页时自动打开抽屉（`isSAEChangeOrderRoute` 检测，`?envName=` 携带环境名，与既有 `?envName=` 深链约定一致），关闭返回环境列表。
