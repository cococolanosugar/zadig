## 1. 背景与评审总结

用户引入 Grok Bot 自动化对账产物（包含 224 条路由、472 条 API 契约逆向比对）。主控（Antigravity）先手拆解为三类：
1. **A 类（真实缺陷）**：共 7 项，分为主控即刻修复的 4 项（P0-05、P0-03、P1-04、P1-03，见 Commit `2f83e5839`）与派发给 ZCode 攻坚的 3 大专项（P1-02/P1-05、P0-02、P0-04）；
2. **B 类（产品与架构边界）**：P0-01（Plutus 客户交付闭源业务）、P0-04（动态插件运行时闭源特性）、P1-01（向导仅支持 K8s 架构决策），维持现状；
3. **C 类（事实性偏差）**：P1-06（系统集成已被全面拆解为 12 大端点与字段映射），予以澄清与驳回。

本次评审对 ZCode 交付的 3 大专项进行严格双重门禁检测与代码审查。

## 2. 三大专项修复详情

### 专项一：模板中心写能力与错误通道（P1-02 & P1-05）
- **错误通道恢复**：在 `frontend/src/api/template.ts` 中移除 7 个列表 API 的静默 `catch { return [] }`，改为异常向上抛出；
- **写能力契约对齐**：补齐 Helm Chart、Build、Scanning 模板的 12 个 CRUD 接口：
  - Chart：`codeHostID`, `owner`, `namespace`, `repo`, `path`, `branch`（对齐后端 `addChartArgs` + `fs.DownloadFromSourceArgs`）；
  - Build：强制传递 `pre_build: { res_req: 'low' }`，有效杜绝后端 `service/build.go:47` 空指针 panic；
  - Scanning：适配 `scanner_type`、`enable_scanner`、Sonar 参数与自定义脚本。
- **界面交互**：`frontend/src/pages/Templates/index.tsx` 新增页面级 `Alert` 错误展示与「重试」机制；为表格注入「操作」列（编辑、二次确认删除）与按模板类别定制的编辑 Drawer/Modal。

### 专项二：SAE 变更单与回滚抽屉（P0-02）
- **后端真实契约校准**：校准至真实挂载路径 `/api/aslan/environment/environments/sae/:envName/app/:appID/changeOrder` 及其 query 参数；
- **核心契约实现**：在 `frontend/src/api/environment.ts` 封装 `listSAEChangeOrders`、`getSAEChangeOrderDetail`、`abortSAEChangeOrder`、`rollbackSAEChangeOrder` 四大核心方法与 `listSAEEnvs`、`listSAEApps` 辅助方法；
- **专属交互抽屉**：新增 `frontend/src/pages/Environments/SAEChangeOrderDrawer.tsx`，支持 SAE 环境与应用二级联动筛选、变更单列表（阿里云状态 0-3 映射 Tag）、变更详情内嵌透传渲染、中止与回滚二次确认弹窗；在 `Environments/index.tsx` 建立 `/sae/changeOrder*` 路由与 `?envName=` 参数深链直达。

### 专项三：工作流插件仓库管理 UI（P0-04 社区能力）
- **插件仓库管理 Card**：在 `frontend/src/pages/Settings/Config/index.tsx` 的「插件管理」Tab 下新增「工作流插件仓库」独立卡片与表格，展示仓库名称、Git URL、所有者、分支、插件数、更新时间及删除 Popconfirm；
- **添加插件仓库 Modal**：集成代码源下拉选择（懒加载 `/api/v1/codehosts`），配合表单校验仓库 URL、所有者与分支；利用 `workflowApi.upsertUserPluginRepo` 在保存时触发后端现场 `git clone` 与清单同步。
