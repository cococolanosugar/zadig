## 2. 真实缺陷 / 缺失清单（A 类）

### P0

#### R2-A1 · 人工审批卡片因任务状态门控过窄而不展示（A · P0）

- **位置**：`frontend/src/pages/Pipelines/Execution.tsx:610`
  ```tsx
  {pendingApproval && task?.status === 'waiting' && (
  ```
- **L3 事实**：审批中 Job/Task 状态为 `wait_for_approval`（`config.StatusWaitingApprove`，`pkg/microservice/aslan/config/consts.go:124`；`job_approval.go` 置 `StatusWaitingApprove`）。`waiting` 是队列等待态（`StatusWaiting`），**不是**审批态。
- **现象**：`findPendingApproval`（:53-62）已能识别 `wait_for_approval` Job，但渲染条件要求 `task.status === 'waiting'`，真实审批场景下 **同意/驳回面板不出现**，用户无法在执行页完成审批闭环。
- **建议**：改为 `pendingApproval && (task?.status === 'wait_for_approval' || task?.status === 'waiting')`，或仅依赖 `pendingApproval`（已含 Job 态判断）。

### P1

#### R2-A2 · 测试产物仅列表、无下载闭环（A · P1）

- **位置**：`Execution.tsx:198-209`、`1015-1040`；`workflowApi.getTestWorkspaceFiles`
- **现象**：拉取 `file_names` 后只渲染文件名；无点击下载、无对接 L3  
  `GET /workflow/v4/workflowtask/workflow/:wf/taskId/:id/job/:job`（`GetWorkflowV4ArtifactFileContent`）或 testing workspace 下载端点。
- **建议**：为每个文件名提供下载按钮（blob/`window.open` 带 Token），并在 `workflowApi` 封装 Artifact GET；失败时 `message.error`（当前 catch 静默空列表，见 R2-A4）。

#### R2-A3 · 构建 Job 产物 API 未进入前端（A · P1）

- **L3**：`router.go:150-151`  
  - `GetWorkflowV4ArtifactFileContent`  
  - `GetWorkflowV4BuildJobArtifactFile`
- **前端**：`workflow.ts` / Execution **零引用**。
- **建议**：执行页 Job 工具栏增加「下载产物 / 构建产物」，封装上述两路径。

#### R2-A4 · JUnit / 产物加载静默失败（A · P1）

- **位置**：`Execution.tsx:191-192`、`205-206` — `catch { setJunitData(null) / setWorkspaceFiles([]) }`，无错误提示。
- **建议**：与任务详情加载一致，`feedback.message.error`；空数据与失败分开展示。

#### R2-A5 · 失败任务「重试」缺少二次确认（A · P1/P2 边界）

- **位置**：`Execution.tsx:549-569` — `retryWorkflowTask` 直接 `onClick`，对比取消/克隆均有 `Popconfirm`。
- **建议**：补 `Popconfirm`（文案：将按失败点重新入队）。

### P2

#### R2-A6 · `setWorkflowBreakpoint` 死代码且契约不完整（A · P2）

- **位置**：`workflow.ts:1136-1140`（DEAD）
- **问题**：无 `operation` query；真正使用的是 `setWorkflowTaskBreakpoint`（带 `operation=set|unset`，对齐 `router.go:143`）。
- **建议**：删除重复方法，避免误用导致无法 unset。

| 方法 | 说明 |

#### R2-A8 · 触发后跳转路径脱离项目深链（A · P2）

- **位置**：`WorkflowTriggerModal.tsx:157` → `navigate(\`/v1/pipelines/${workflowName}/task/${taskId}\`)`
- **影响**：可用（存在全局 `pipelines/:name/task/:taskId` 路由），但丢失 `/projects/detail/:projectName/...` 上下文，依赖 Zustand `currentProject`。
- **建议**：优先跳转项目内执行深链，与列表页导航一致。

#### R2-A9 · 触发失败时吞掉非响应错误（A · P2）

- **位置**：`WorkflowTriggerModal.tsx:158-160` — 仅当 `response.data.message` 存在才 `message.error`，校验失败/网络错误可能无反馈。
- **建议**：统一 `err.message` 兜底。
