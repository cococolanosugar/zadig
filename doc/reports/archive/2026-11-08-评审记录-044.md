## 1. 审查背景与穿透核查成果

本轮为用户指示的「十轮全流程逆向交叉循环特战」第四轮（Loop 04），聚焦工作流实时执行日志与 Web 终端（Pod Exec）通信链路：SSE 日志流帧格式、WebSocket 终端交互、xterm 渲染性能、以及任务归档日志拉取。

ZCode 作为独立只读审计员，深入后端 `shared/handler/sse.go`、`workflow/service/workflow/ws_terminal.go`、`log/handler/router.go` 以及前端实现进行了逐字段协议对账，核验确证：
- **协议帧与 WS 交互 100% 对齐**：`TerminalMessage{operation, data, rows, cols}` 逐字段对齐，前端仅发送 `stdin` 与 `resize`，坚决不发 heartbeat（避免后端 unknown-operation 断连），xterm 带有 `FitAddon` 与 10000 行缓冲区；
- **LOOP4-B1 (B 类 · 关键运行缺陷)**：后端 SSE 日志流通过 gin `c.SSEvent("message", ...)` 推送日志，在容器日志读完正常关流时直接关闭连接（无自定义 done 事件）。而前端 `subscribeSSE` 原将 `reader.read()` 返回的 `done: true` 视为非正常连接中断并触发 `scheduleReconnect`，配合 `LogViewer` 默认 `autoReconnect: true`，导致任务正常结束后依然无谓重连 5 轮，每次重试重复拉取 1000 行历史日志造成重复刷屏与无效网络开销。
- **LOOP4-B2 (B 类 · 归档日志缺失)**：后端 `GET /api/aslan/logs/log/v4/workflow/:workflowName/tasks/:taskID/jobs/:jobName` 归档日志端点后端完备，但前端此前零消费，用户在实时 tails 窗口外无法获取完整全量执行日志。

## 2. 复核与修复实施细节

主控 Antigravity 独立复核确认上述缺口存在后，向 Cursor 下发修复规范 `scratch_cursor_loop_04_spec.txt`，完成端到端闭环修复：

1. **[`sse.ts`](file:///D:/work/zadig/zadig/frontend/src/utils/sse.ts)**：
   - 扩展 `SSEOptions` 接口，新增 `onComplete?: () => void` 正常流结束回调；
   - 修正 EOF 判定：当 `reader.read()` 返回 `done: true` 时，判定为服务端日志推流正常结束，执行 `options.onComplete?.()` 并安全退出，**绝不调用 `scheduleReconnect`**，彻底根治日志流结束后的多轮重复重试问题。

2. **[`workflow.ts`](file:///D:/work/zadig/zadig/frontend/src/api/workflow.ts)**：
   - 封装强类型接口 `getWorkflowJobArchiveLogs(workflowName, taskId, jobName): Promise<string>`，连接后端 `/api/aslan/logs/log/v4/workflow/:workflowName/tasks/:taskID/jobs/:jobName` 归档日志端点，注入 `{ skipErrorHandler: true }` 防止未归档前弹出全局阻断性提示。

3. **[`LogViewer.tsx`](file:///D:/work/zadig/zadig/frontend/src/components/Terminal/LogViewer.tsx)**：
   - 增加 `onDownloadArchive?: () => Promise<string | void> | void` 属性；
   - 新增 `triggerTextDownload` 通用文件下载驱动；
   - 工具栏状态强化：当日志流收到 `onComplete` 时，控制台输出 `[日志流已正常结束]` 并渲染绿色 `<Tag>已结束</Tag>` 标签；
   - 独立分离「下载当前窗口日志」与「下载完整归档日志（`<CloudDownloadOutlined />`）」按钮，提供清晰的用户操作心智。

4. **[`Execution.tsx`](file:///D:/work/zadig/zadig/frontend/src/pages/Pipelines/Execution.tsx)**：
   - 在工作流任务详情页实现 `handleDownloadArchiveLogs`，自动拼装工作流名称、任务 ID 与当前选中 Job，传入 `<LogViewer onDownloadArchive={handleDownloadArchiveLogs} />`，实现工作流执行界面 Job 完整归档日志一键下载闭环。
