## 1. 审查背景与对账总览

本轮聚焦 Zadig 系统中核心的「效能洞察（Insights）」、「工作台（Dashboard）」与「报表统计（Statistics）」模块。
审计重点穿透四大核查维度：
1. **工作台概览卡片契约与数据流**：工作台概览卡片配置加载、动态卡片数据拉取（运行中工作流、部署效能、回滚排行榜等）；
2. **研发效能五维雷达与端点消费**：后端 `v2/ai/radar` 契约与前端展示对齐；
3. **自定义仪表盘配置持久化 (Dashboard V2)**：`v2/config` 指标项 CRUD、权重、外源配置契约；
4. **图表组件健壮性与防呆降级机制**：空数据兜底、防伪造数据。

## 2. 深度穿透核查成果与缺陷清单

### 缺陷 1 (LOOP7-A1 · A 类 · 关键运行阻断)：工作台部署与回滚卡片因缺少必填查询参数导致后端 HTTP 500 全面崩溃

- **后端真实契约证据**：
  - 后端接口：`GET /api/aslan/stat/v2/quality/deploy/health` 与 `GET /api/aslan/stat/v2/quality/rollback/service/top`
  - 源码位置：`pkg/microservice/aslan/core/stat/handler/deploy_stat_v2.go:42-59` 与 `rollback_v2.go:70-81`
  - 绑定参数结构：
    ```go
    type getStatGeneralReq struct {
        StartTime      int64                 `json:"startDate"  form:"startDate"`
        EndTime        int64                 `json:"endDate"    form:"endDate"`
        Projects       []string              `json:"projects"   form:"projects"`
        ProductionType config.ProductionType `json:"type"       form:"type"`
    }
    ```
  - 底层数据库查询校验：`pkg/microservice/aslan/core/common/repository/mongodb/job_info.go:217-238`：
    ```go
    switch productionType {
    case config.Production:
        query["production"] = true
    case config.Testing:
        query["production"] = false
    case config.Both:
        break
    default:
        return nil, fmt.Errorf("invlid production type: %s", productionType)
    }
    ```
  - **严重故障机理**：
    若请求未携带 `type`（或 `type` 不是 `production`、`testing`、`both` 之一），后端 `switch productionType` 直接命中 default 并返回 `invlid production type: `（HTTP 500 致命错误）！
    此外，若 `startDate` 和 `endDate` 未传，则时间戳为 0，`query["start_time"] = bson.M{"$gte": 0, "$lt": 0}` 查不到任何数据。
- **前端现状缺陷行号**：
  - `frontend/src/pages/Dashboard/index.tsx:149`：
    ```ts
    // 致命缺陷：未传 startDate、endDate 和 type
    const health = await http.get<{ success?: number; failure?: number }>(
      '/api/aslan/stat/v2/quality/deploy/health',
      { skipErrorHandler: true }
    );
    ```
  - `frontend/src/pages/Dashboard/index.tsx:173`：
    ```ts
    // 致命缺陷：仅传 top=5，缺少 startDate、endDate、type=both
    const res = await http.get<Array<{ project_name?: string; service_name?: string; count?: number; production?: boolean }>>(
      '/api/aslan/stat/v2/quality/rollback/service/top?top=5',
      { skipErrorHandler: true }
    );
    ```
- **影响后果**：
  任何用户进入首页「工作台（Dashboard）」时，「部署效能统计」卡片与「服务回滚排行榜」卡片恒定触发后端 500 异常并进入 catch 块降级，永远显示 `0 次 / -`，整个工作台核心效能卡片完全瘫痪。
- **修复方案**：
  改用强类型封装方法：
  - 使用 `statApi.getDeployHealthStats({ startDate: start, endDate: end, type: 'both' })`；
  - 使用 `statApi.getTopRollbackedServices({ startDate: start, endDate: end, top: 5, type: 'both' })`；
  默认时间范围取近 30 天（`end = Math.floor(Date.now() / 1000); start = end - 30 * 86400`）。

### 缺陷 2 (LOOP7-A2 · A 类 · 核心模型未消费)：研发效能五维雷达契约零消费

- **后端真实契约证据**：
  - 后端路由：`GET /api/aslan/stat/v2/ai/radar`（`pkg/microservice/aslan/core/stat/handler/router.go:85`）
  - 核心计算服务：`pkg/microservice/aslan/core/stat/service/stat_v2.go:613-670`
  - 返回模型：
    ```go
    type EfficiencyRadarData struct {
        Name                           string  `json:"name"`
        Alias                          string  `json:"alias"`
        TestSuccessRate                float64 `json:"test_success_rate"`
        ReleaseFrequency               float64 `json:"release_frequency"`
        BuildFrequency                 float64 `json:"build_frequency"`
        ReleaseSuccessRate             float64 `json:"release_success_rate"`
        RequirementDevelopmentLeadTime float64 `json:"requirement_development_lead_time"`
    }
    ```
    代表研发效能体系中的 5 大核心支柱：测试质量（测试通过率）、发布质量（发布成功率）、构建通量（构建频次）、发布速度（发布频次）、交付周期（需求研发周期）。
- **前端现状缺陷行号**：
  - `frontend/src/api/stat.ts:342` 虽然声明了 `getEfficiencyRadar`，但返回类型为弱类型 `Promise<any>`；
  - `frontend/src/pages/Insights/index.tsx` 中搜索 `getEfficiencyRadar` 为 **0 引用**，效能洞察概览页面仅展示了基础 KPI 卡片和折线/饼图，五维雷达模型完全缺失。
- **影响后果**：
  效能洞察作为企业级研发度量看板，缺失了最关键的研发效能五维体检能力。
- **修复方案**：
  1. 在 `frontend/src/api/stat.ts` 补充 `EfficiencyRadarData` 强类型接口并绑定到 `getEfficiencyRadar`；
  2. 在 `frontend/src/pages/Insights/index.tsx` 的 `fetchInsightData` 中并发请求 `statApi.getEfficiencyRadar(startDate, endDate, currentProject ? [currentProject] : undefined)`；
  3. 在效能概览中呈现「研发效能五维指标与交付健康度」结构化卡片，涵盖 5 大维度的实时数值与健康评级。

### 缺陷 3 (LOOP7-B1 · B 类 · API 契约与体验治理)：统计报表中心无项目参数时避免发送孤儿查询

- **对账分析**：
  - `frontend/src/pages/Statistics/index.tsx` 与 `frontend/src/pages/Insights/index.tsx`：当全局未选中项目或切换项目时，时间戳与请求参数必须保持秒级精度统一（`Math.floor(Date.now() / 1000)`）。
  - 图表在空数据状态下统一以 Ant Design 标准 `<Empty image={Empty.PRESENTED_IMAGE_SIMPLE} />` 降级，杜绝任何假数据或 NaN% 渲染。
