  }

  `CreateCollaborationMode`/`UpdateCollaborationMode` 首先执行该校验，失败返回 `members and member_info not match`。
- 官方真理源：`75.*.js` 组件 `changeUserOrGroup`：

  var t = this.currentUsers.concat(this.currentGroups).filter(u => e.includes(u.uid || u.gid));

### P0-3 更新请求契约错误 + 覆盖式清空 products/workflows（编辑即破坏）

- 前端：`api/collaboration.ts:79-88` 只把 `projectName` 放在 query；`CollaborationDrawer.tsx:134-139` 的 body 无 `project_name`、无 `products`、无 `workflows`。
- 后端 Handler：`collaboration/handler/collaboration_mode.go:94-137` 完全从 **body** 读取 `args.ProjectName`（不读 query）：
  - 非系统管理员：`ProjectAuthInfo[""]` 不存在 → `UnAuthorized`（403）；
  - 系统管理员：跳过鉴权，进入 `service.UpdateCollaborationMode` → `mongodb/collaboration_mode.go:89-116` 以 `name + project_name` 查询，`project_name` 为空 → `UpdateOne` 匹配不到任何文档 → **不报错、静默成功**。
- 覆盖语义：`mongodb/collaboration_mode.go:100-109`
  ```go
  change := bson.M{"$set": bson.M{
      "members": args.Members, "member_info": args.MemberInfo,
      "workflows": args.Workflows, "products": args.Products, ...
  }}
  ```
  前端不传 `workflows/products` → 反序列化为 `nil` → **编辑名称/成员会把该模式已配置的全部环境与工作流绑定清空**。
- 附带：`$set` 不含 `deploy_type`（`:100-109`），表单里修改部署架构不会生效。
- 修复：`update` body 必须携带 `project_name`、`deploy_type`、`products`、`workflows`（从当前记录完整回填后只改差异字段）；建议后端 `$set` 增加 `deploy_type`，或在 handler 中拒绝 `project_name` 与 URL `:name` 不一致的请求。

### P0-4 协作模式配置与“实例初始化”链路整体缺失 → 协作模式无法产生任何资源

- 前端现状：`CollaborationDrawer.tsx:128-161` 仅创建空模式；`:142-149` 硬编码 `products: []`、`workflows: []`；`:117-126` 编辑仅回填 name/members/deploy_type/recycle_day。整个前端无任何组件选择“基准环境/基准工作流”、无独占/共享配置、无权限勾选。
- 后端/官方要求：
  - 模式必须包含 `products: ProductCMItem[]`（`name`=基准环境、`collaboration_type`、`recycle_day`、`verbs`）与 `workflows: WorkflowCMItem[]`（`workflow_type/name/display_name/collaboration_type/verbs`）（`collaboration/repository/models/collaboration_mode.go:45-59`）。
  - 官方 UI（`75.*.js`）包含 i18n：`baseWorkflow/baseEnvironment/selectBaseWorkflow/selectBaseEnvironment`、`exclusive（Members create a new workflow based on this base workflow）/shared`、`allPermissions/permissions`、`recyclePolicy`，并按 `policy.workflow.{newPermi,sharePermi}` 等渲染权限复选框。
  - 官方实例初始化页（`71.*.js`）：
    1. `getNewCollaborationAPI(projectName)` 获取待派生资源；
    2. 对 `collaboration_type==='new'` 的 Helm 产品，将 `chartValues[].yaml_data` 转换为 `valuesData`（repo/variableSet ）、`services` 标记 `canEditYaml`；
    3. 按 `name + collaboration_type` 去重；
    4. 以 `base_name` 建立 `baseEnvObj`，通过 `InitEnvDialog` 读取基准环境的全局变量/服务默认变量并允许调整；
    5. `createEnvAndWorkflow()` 仅提交 `product.filter(p => p.collaboration_type === 'new')` → `initializeCollaborationAPI`（即 `POST /collaborations/sync`）。
  - 后端 `service/collaboration_instance.go:536-556` 的 `SyncCollaborationInstance` 才会真正创建派生环境/工作流并写入实例、权限。
- 新前端的分支判断缺陷：`CollaborationDrawer.tsx:282-301` 仅在 `syncStatus?.ifSync` 为 true 时展示“立即同步实例”。而后端 `ifSync` 仅在**没有新增资源、只有更新/删除**时为 true（`service/collaboration_instance.go:767-776`）：
  ```go
  ifSync := len(newWorkflow)==0 && len(newProductName)==0 && (Update||Delete)
  ```
  → 只要存在新环境/工作流（即协作模式的核心场景），`ifSync=false`，UI 永不提示，也永不调用 sync → **新协作模式永远无法派生专属环境/工作流**。
- 影响：协作模式在 UI 中可创建但无任何实际效力；成员在项目内看不到派生环境/工作流；所谓“跨项目/多环境协同交付”无从发生。
- 修复：新增协作初始化流程（模态或独立页面）：
  - 进入项目时调用 `GET /collaborations/new`（不依赖 ifSync）；
  - 按官方逻辑过滤 `new`、转换 Helm `valuesData`、去重、展示基准环境信息并允许编辑默认值/变量；
  - 提交 `POST /collaborations/sync?projectName=`，body `{products: <filtered new products>}`；
  - 成功后刷新环境/工作流列表并提示“项目更新成功，环境更新可能需要一些时间”。

1. **协作类型枚举错误**：`api/collaboration.ts:5、14` 使用 `'share' | 'exclusive'`；后端只有 `share` 与 `new`（`collaboration/config/consts.go:23-26`；官方 i18n `exclusive` 对应值 `new`）。任何按类型分支的逻辑都会落空。
2. **成员/用户组选择缺失**：`CollaborationDrawer.tsx:363-370` 使用 `Select mode="tags"` 自由输入“账号”，而 `Members` 需要 **UID/GID**（`collaboration/service/collaboration_instance.go:319-328` 用 uid + 用户组 gid 匹配；`types.Identity{identity_type, uid, gid}`）。无法选择用户组；无法展示成员姓名（列表 `:191-207` 直接显示 UID）。

6. **ShareEnv 拓扑数据为推断值且含无依据文案**：`CollaborationTopologyDrawer.tsx:266-268` 以“子环境服务清单 − 基准服务清单”推断“独占/回落”，未读取任何 VirtualService/流量规则；`Alert :160-173` 宣称“节省 80% 以上集群计算资源”为无数据支撑的营销文案；且新前端无创建子环境的入口（环境创建/更新未暴露 `share_env`，后端支持见 `environment/service/environment.go:2989、3296`）。

8. **服务独占编辑锁是本地假保护**：`Services/index.tsx:125-158` 的 `serviceLocks` 仅为 React `useState`，`handleToggleLock` 不发任何请求；全仓 Go 无编辑锁接口（检索 `EditLock/serviceLock/lock` 无结果）。`isLockedByOther`（`:138-143`）只可能由本地状态构造，跨用户/刷新即失效，“已被 X 独占锁定”分支不可达，却对外宣称“防并发覆盖保护”。保存守卫 `:368-372` 因此是伪保护。

## 五、准确数据结构契约与后端真实 API

### 5.1 数据模型（`collaboration/repository/models/`）

```ts
// CollaborationMode
{
  id?: string;
  project_name: string;          // 单项目，不支持跨项目
  name: string;
  revision: number;              // 每次更新 +1，用于实例 diff
  members: string[];             // user uid / group gid
  member_info: Identity[];       // 必须与 members 一一对应
  is_deleted: boolean;
  deploy_type: string;           // "k8s" | "helm"
  recycle_day: number;           // 0 = 永不回收
  workflows: WorkflowCMItem[];
  products: ProductCMItem[];
  create_time: number; update_time: number;
  create_by: string; update_by: string;
}

Identity = { identity_type: 'user' | 'group'; uid?: string; gid?: string }

WorkflowCMItem = {
  workflow_type: string;         // custom workflow 判定：custom / release workflow
  name: string;                  // 基准工作流名
  display_name: string;          // 只读回显，不落库
  collaboration_type: 'share' | 'new';
  verbs: string[];
}

ProductCMItem = {
  name: string;                  // 基准环境名
  collaboration_type: 'share' | 'new';
  recycle_day: number;
  verbs: string[];
}
```

实例（`collaboration_instance.go`）：`{project_name, collaboration_name, user_uid, policy_name, revision, recycle_day, workflows: WorkflowCIItem[], products: ProductCIItem[]}`；派生资源名为 `pinyin(mode)-base-identityType-user`（`service/collaboration_instance.go:362-378`）。

### 5.2 API（真实路径）

| 能力 | 路径 | 说明 |
|---|---|---|
| 列表 | `GET /api/aslan/collaboration/collaborations?projectName=` | 响应 `{collaborations: CollaborationMode[]}`；**无鉴权**（`handler/collaboration_mode.go:38-47` 使用 `NewContext`） |
| 创建 | `POST /api/aslan/collaboration/collaborations?projectName=` | body `CollaborationMode`；必须含 `project_name/member_info/products/workflows`；项目管理员及以上（`:49-92`） |
| 更新 | `PUT /api/aslan/collaboration/collaborations/:name?projectName=` | URL `:name` 未被使用；以 body `project_name/name` 定位；body 缺失 `products/workflows` 会被清空（`:94-137`、`mongodb:89-116`） |
| 删除 | `DELETE /api/aslan/collaboration/collaborations/:name?projectName=` | 软删除 + 重置实例 revision（`:139-169`） |
| 待初始化检查 | `GET /api/aslan/collaboration/collaborations/new?projectName=` | 返回 `{code:10000, workflow[], product[], ifSync}` 或空；**无鉴权** |

### 5.3 `sync` 请求的 Product 结构（`service/collaboration_instance.go:95-107`）

```ts
Product = {
  collaboration_type: 'share' | 'new';
  base_name: string;            // 基准环境名
  collaboration_mode: string;
  name: string;                 // 派生环境名（new 类型）
  deploy_type: 'k8s' | 'helm';
  default_values?: string;
  global_variables?: GlobalVariableKV[];
  valuesData?: {                // Helm values 来源（官方由 yaml_data 转换）
    autoSync?: boolean;
    yamlSource?: 'repo' | 'variableSet';
    gitRepoConfig?: { branch; codehostID; owner; repo; valuesPaths: string[]; autoSync; namespace };
    source_id?: string;
  };
  yaml_data?: CustomYaml;
  chartValues?: HelmSvcRenderArg[];
  services?: K8sSvcRenderArg[]; // k8s 派生环境必需
}
```

### 5.4 枚举与 verbs

- `CollaborationType`：`share`（共享同一基准资源）、`new`（为成员新建派生资源）。
- 工作流 verbs：`get_workflow / edit_workflow / run_workflow / rollback_workflow / debug_workflow`。
- 环境 verbs：`get_environment / config_environment / manage_environment / restart_environment / rollback_environment / scale_environment / debug_pod`。
- 生产环境 verbs：`get_production_environment / config_production_environment / edit_production_environment / restart_production_environment / rollback_production_environment / scale_production_environment / production_debug_pod`。
  （`handler/collaboration_mode.go:171-195`、`pkg/types/authz.go:33-52`）

### 5.5 权限边界（无“协作模式 ID 注入”）

- 工作流执行鉴权由后端按**工作流名**查询协作实例：`workflow/handler/openapi.go:50-51、405、447-448`、`workflow_task_v4.go:90-91` → `GetCollaborationModePermission(uid, project, workflow, name, run)`（`pkg/shared/handler/base.go:188-193`）。
- 请求体/query **不存在** collaboration mode id 参数；隔离依靠“派生资源名 + 实例 verbs”实现。任务书“正确传递协作模式 ID”的前提不成立。
- 环境权限同理通过 `CheckPermissionGivenByCollaborationMode`（`environment/handler/*` 多处）按环境名判定。

### 5.6 ShareEnv（与协作模式正交）

- 开启/关闭/就绪：`POST|DELETE /environments/:name/share/enable`、`GET /environments/:name/check/sharenv/:op/ready`（`environment/handler/router.go:191-193`）。
- 流量规则：Istio `x-env` Header（`environment/service/share_env.go:52`）；子环境通过产品创建/更新体的 `share_env {enable, is_base, base_env}` 建立（`environment/service/environment.go:2989、3296`）。
- **不存在**“同步基准环境”接口。
