## 5. 静默吞错与体验缺陷清单

### 5.1 页面层静默吞错

**独立扫描结论：0 处**。对 `frontend/src` 全部 `.ts/.tsx` 执行逐 catch 块深度解析（block 内无 feedback/notification/rethrow 且仅注释即命中），页面与组件层**零命中**。R5（模板/错误通道）、R6（测试/扫描附属加载）、R7（Insights 三函数 + Detail 聚合判定）、R10（基础镜像/批量部署）等轮次的治理已系统化清零。

### 5.2 API 层语义化默认值（C 类 · 合理降级，非缺陷）

约 20 处 API 层 `catch → 语义默认值`（`getFeature → {enabled:false}`、`getEmailHost → null`、`getLicense → {}`、`checkWorkloadsK8sServices → false`、notification 列表 → []、`checkJenkinsExist → {exist:false}`、`checkLLMIntegration → {enabled:false}` 等），均为**可选配置探测/特性开关/社区版探活**语义，带注释说明，调用方按默认值呈现对应 UI 状态，不掩盖主数据路径故障。判定 C 类合理降级；其中 `getLicense` 在社区部署下返回 `{}` 驱动 Enterprise 页"未激活"态（R11 已改为真实 status 驱动），行为正确。

### 5.3 体验观察项（C 类 · 记录不阻塞）

1. `blueking`/`dms`/`grafana` 三组后端路由存在（system router.go:122/467/479），但 REA 官方前端在证据窗口内**未调用**，Integration monitor 类目已用 `observability` 契约覆盖监控语义 → 观察项（非 REA 证据缺口，建议保持现状）；
2. Delivery「批量交付部署」为社区无对应后端路由的引导式占位（R10 设计决策，info 提示 + 引导至工作流/发布计划）→ C 类；
3. `POST /stat/quality/testTrend` 已被 `/stat/v2/quality/test/dailyHealthTrend` 替代（Quality 页 testTrend 状态由 v2 端点驱动，验证一致）→ C 类版本演进。
