## 2. A 类真实缺陷清单

### P0

本轮**未发现**与 R4-A3 / R5-A1 同级的「失败仍提示成功」P0。  
扫描取消、测试触发/重启/删模块主路径均有 `feedback.message.error`。

### P1

#### R6-A1 · 测试任务取消 `CancelTestTaskV3` 完全未接线（A · P1）

- **L3**：`router.go:107` `DELETE /testtask` → `CancelTestTaskV3`（query: `projectName` / `testName` / `taskID`）
- **前端**：`Quality/index.tsx` 任务操作列（约 `:1825-1838`）仅「详情/报告」「重启」「产物」；全文件 **无** `http.delete('/api/aslan/testing/testtask...')`，无 `handleCancelTask`
- **影响**：运行中测试无法从质量中心取消，只能依赖后端超时或外部手段；与扫描页已具备取消形成能力断层
- **建议**：运行中状态显示「取消」+ Popconfirm → `DELETE /api/aslan/testing/testtask?projectName=&testName=&taskID=`；失败 `message.error`，成功后刷新任务列表与 SSE

#### R6-A2 · 成功率缺省回落硬编码 `100%`（A · P1 · 假数据）

- **位置**：`Quality/index.tsx:771`
  ```ts
  value={tests.length > 0 && stats.pass_rate !== undefined ? `${stats.pass_rate}%` : (tests.length > 0 ? '100%' : '-')}
  ```
- **对照**：`GET /stat/v2/quality/test/count` 失败或未返回 `pass_rate` 时，有测试用例却展示满分成功——属于乐观假指标
- **建议**：无 `pass_rate` 时显示 `-` 或「暂无统计」；禁止默认 `100%`

#### R6-A3 · 质量度量契约部分缺口 / API 死代码（A · P1/P2）

| L3 / API | 前端现状 |
| --- | --- |
| `GET /stat/v2/quality/test/recentTask` | `statApi.getRecentTestTasks` **已封装，全仓零调用** |
| `POST /stat/quality/testCaseMeasure` | ❌ 未封装、未用 |
| `POST /stat/quality/testTrend` | ❌（页面用 v2 `dailyHealthTrend` 部分等价） |
| `POST /stat/quality/testDeliveryDeploy` | ❌ |
| `POST /stat/quality/initTestStat` | ❌（运维向，可 B） |
| `GET quality center /tests` `ListTestingWithStat` | ❌（列表走 `/testing/test` + count，功能近似） |

- **建议**：大盘增加「最近测试任务」卡片接 `getRecentTestTasks`；按 EE 图表决定是否补 case/delivery 度量；清理或接线死 API

#### R6-A4 · 测试/扫描详情附属加载静默失败（A · P1/P2）

| 位置 | 行为 |
| --- | --- |
| `Quality/index.tsx:273-274` | 详情 GET 失败保留列表行，无提示 |
| `:283-284` | 任务列表失败 → `[]` |
| `:224-229` / `:250-253` | 部署/测试趋势 catch 静默清零 |
| `Scanners.tsx:352-353` / `:363-364` | events / artifact_info 静默 |
| `:451` / `:463` | 详情/任务列表附属 catch |

- **主列表** `fetchData` / 扫描列表已有 `message.error`（正向）
- **建议**：抽屉内失败至少 `message.warning`；图表区可保留空态但避免与「全成功」视觉混淆

### P2

#### R6-A5 · `workflow.ts` 测试域封装过窄（A · P2）

- 仅有工作流侧 `getTestJunitReport`（itreport workflowv4）与 `getTestWorkspaceFiles`
- Quality 页大量直连 `http.*` `/testing/test*` / `testtask*`，与规范「相关 API：workflow.ts」不完全对齐
- **建议**：抽取 `testingApi` 或扩展 `workflow.ts`/`stat.ts`，统一 testtask CRUD+cancel+restart

#### R6-A6 · 扫描 SSE / events URL 未显式附带 `projectName`（A · P2）

- **位置**：`Scanners.tsx:1811` `.../sse`；events `:348` 亦无 query
- **L3**：handler 使用 `FindScanningProjectNameFromID`，通常可从 scanning id 反查项目
- **风险**：跨项目/权限边界或中间件变更时脆弱；artifact 下载已带 `projectName`（不一致）
- **建议**：与 cancel/artifact 对齐，统一追加 `?projectName=`

#### R6-A7 · `workspace/testing/:testName/taskId/:taskId` 未直接使用（A · P2 / 见 C）

- Quality 产物走 `GET /testtask/artifact`（`GetTestingTaskArtifact`），与 workspace V2 并行存在；属路径选择而非功能全缺

#### R6-A8 · `rowKey` 使用 `Math.random()` 兜底（A · P2）

- `Quality/index.tsx:1776` `rowKey={(r) => String(r.task_id || r.id || Math.random())}` — 无 id 时每次 render 换 key，可能导致行状态抖动
- **建议**：稳定合成 key（index + create_time）
