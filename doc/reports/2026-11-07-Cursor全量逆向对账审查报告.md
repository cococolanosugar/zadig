## 2. 发现的功能缺失 / 瑕疵清单

### 2.1 P0（阻塞 / 严重）

**本次独立审查未发现仍存活的社区侧 P0。**  
此前最高危项「构建误触发任意工作流」与「Dashboard 杜撰接口」均已消除。

> 若产品将「移动端测试/环境深链完整保留」定义为发布阻塞，可将 §2.2 P1-R1 提升为发布门禁，但技术严重性低于误执行类缺陷。

### 2.2 P1（重要）

#### P1-E1 · API 层模式性静默吞错（A）

- **现象**：`catch { return [] | null | {} }` 在 `frontend/src/api/` 仍有 **44** 处（全 `src` 共 46，另 2 处在页面）。列表失败时页面易显示「空数据」而非错误 Alert/重试。
- **高影响样例**：

| 文件 | 行号（约） | 方法族 | 风险 |
| --- | --- | ---: | --- |
| `api/workflow.ts` | 329, 526, 588 | `getWorkflows` / `listGeneralHooks` / 相关列表 | 工作流列表/触发器静默空表 |
| `api/settings.ts` | 258–783（多处） | codehosts / registries / storage / 集成列表 | 设置页「无配置」误导 |
| `api/rbac.ts` | 68–164 | 角色/成员列表 | 权限页假空 |
| `api/service.ts` | 320–419 | codehost 辅助 & yaml 模板列表 | 导入服务向导假空 |
| `api/notification.ts` | 39, 74 | 通知列表 | 铃铛假空 |
| `api/project.ts` | 52, 71 | 项目列表兜底 / 分组 | 项目页假空 |

- **官方/规范依据**：规范书 Checklist §2；方法论 v2.0「故障与真空态不得混淆」。
- **建议**：列表/详情 GET 默认上抛；仅对「可缺省的附属下拉」（如代码源命名空间）保留吞空，并在 UI 明示「加载失败」。模板中心已验证的 Alert+重试模式可复用。

#### P1-R1 · 移动端深链覆盖不全（A）

- **已修好**：`/mobile/projects/detail/:projectName`、workflows(+taskId) 经 `useParams` 插值到桌面路由。
- **仍缺失**：`/mobile/.../tests/*`、`/mobile/.../envs/*`（含 k8s/helm/pm）落入 `/mobile/*` → `/v1/dashboard`，**上下文丢失**（inventory ee-186~191）。
- **依据**：L2 `routes.csv`；`router/index.tsx:309-317`。
- **建议**：为 tests/envs 补同等 Redirect 组件，或明确文档声明「移动端仅支持项目/工作流深链」。

#### P1-R2 · SAE 应用详情深链无专属 UI（A，部分）

- **现状**：`/envs/sae/changeOrder*` 已打开变更单抽屉（A→已修复）。  
  `/envs/detail/:app_id/sae*`（inventory ee-053~058）仍由 `envs/detail/:serviceName/*` → `ServiceDetailPage` 通用承接，**无 SAE 应用级专属详情**。
- **L3**：后端 `environment/handler/router.go` SAE 组已就绪；社区部署另受 `CheckZadigLicenseFeatureSae` 门控（失败应展示许可错误，不宜静默空表——抽屉侧已做到）。
- **建议**：补 SAE 应用详情壳（应用信息/变更单入口），与现有 Drawer 串联；inventory「缺失」应对 changeOrder 行降级为「部分」。

#### P1-W1 · Jira / Meego（飞书）Hook 仅有 API 桩、无编排 UI（A）

- **证据**：`workflowApi.getJiraHooks/addJiraHook/...`、`addLarkHook/...` 已定义；`TriggerPanel.tsx` 仅实现 Git Webhook + General Webhook，**零** jira/meego 引用。
- **依据**：L2 官方触发器面板；L3 `workflow/handler/router.go` jirahook/meegohook 组。
- **建议**：在 `TriggerPanel` 增 Tab，接线现有 API；避免「台账已完成、UI 未接线」再次发生。

#### P1-S1 · SSE 日志流无断线重连（A）

- **证据**：`utils/sse.ts` 流结束/错误仅 `onError`，无退避重连；`LogViewer.tsx:161-163` 打印「日志流已结束」后停止。
- **规范**：Checklist §4「SSE 断线重连与 ANSI 限频」。
- **建议**：在 `subscribeSSE` 增加可取消的指数退避重连；对运行中任务默认开启。
