## 2. 缺陷清单

### P0

本轮**未发现**「失败仍 message.success」或「纯内存假持久化」级 P0。  
删除/保存主路径均 `await` 真实 `templateCrudApi` 后再提示。

### P1

#### R9-A1 · 服务引用查看与一键同步几乎全缺（A · P1）

| L3 | API 层 | Templates UI |
| --- | --- | --- |
| `GET/POST /yaml/:id/reference` | ❌ | ❌ |
| `GET /dockerfile/:id/reference` | ❌ | ❌（无 Sync POST） |
| `GET/POST /charts/:name/reference` | GET ✅ / POST ❌ | ❌ |
| `GET /build/:id/reference` | ❌ | ❌ |
| `GET /scanning/:id/reference` | ❌ | ❌ |

- **影响**：模板变更后无法在中心查看引用方，也无法 `Sync*TemplateReference` 推送到服务 — 规范「服务引用与一键同步」核心闭环断裂
- **建议**：统一 Reference Drawer（列表 service/project）；确认后 `POST .../reference`；Chart 先接线已有 `getChartTemplateReference`

#### R9-A2 · YAML 变量提取/校验、Dockerfile 校验仅 API 死代码（A · P1）

- **已封装**：`extractYamlVariables`、`validateYamlVariable`、`validateDockerfile`（`template.ts:133-151`）
- **UI**：编辑 Modal 无「提取变量」「校验变量」「校验 Dockerfile」按钮；全仓 Templates 页零调用
- **对照**：后端 `CreateYamlTemplate`/`Update` 会自动 extract+validate content；Dockerfile Create/Update 亦调 `ValidateDockerfileTemplate` — 保存路径有服务端保障，但**交互期预检与变量 YAML 独立编辑**缺失（另有 `PUT /yaml/:id/variable` 前端未接）
- **建议**：编辑器工具栏接预检；变量区支持 `validateVariable` + `UpdateYamlTemplateVariable`

#### R9-A3 · Chart 变量编辑与文件浏览未接线（A · P1）

- **L3**：`GET/PUT /charts/:name/variables`、`GET /:name/files`
- **现状**：`getChartTemplateVariables` / `saveChartTemplateVariables` / `getChartTemplateFiles` 已封装；编辑 Modal 仅代码源坐标字段，**无** variables 表单、无 files 预览
- **建议**：编辑 Drawer 增加 Variables Monaco + 保存；可选文件树预览

#### R9-A4 · 工作流 / 发布计划模板无中心 CRUD（A · P1）

| L3 | 前端 |
| --- | --- |
| workflow POST/PUT/GET/DELETE | 仅 `getWorkflowTemplates` 列表 + 卡片查看 |
| release_plan 全 CRUD | 仅 `getReleasePlanTemplates` 列表，无操作列 |

- **UI**：`openCreateTemplate` 对 workflows/releasePlan 仅 `message.info('该类模板由对应功能模块内创建...')`（`:85`）
- **建议**：至少补 release_plan 中心 CRUD；workflow 明确只读内置 vs 自定义可删；或深链到工作流「另存为模板」

#### R9-A5 · YAML 自代码源 preload/load/sync 未接（A · P1/P2）

- **L3**：`POST /yaml/preload/:codehostId`、`POST|PUT /yaml/load/:codehostId`
- **前端**：零命中 — 只能手写 content，无法从 Git 批量导入/同步 YAML 模板

### P2

#### R9-A6 · 编辑器非 Monaco，语法高亮弱（A · P2）

- **位置**：`Templates/index.tsx:929+` `Input.TextArea` monospace；查看 Drawer 亦为纯文本 pre
- **规范**：要求 Monaco YAML/Dockerfile 集成
- **建议**：复用项目已有 Monaco 组件，按 kind 设 `language: yaml|dockerfile|shell`

#### R9-A7 · `flatkvs` / 系统变量展示不足（A · P2）

- L3 `POST /yaml/flatkvs`；列表响应可含 `system_variables` — UI 未展示系统变量帮助

#### R9-A8 · CRUD 普遍 `skipErrorHandler: true`（A · P2）

- `templateCrudApi` 全员 skip；`handleSaveEditing` 仅当 `err instanceof Error` 有 message 才提示 — Axios 业务错误形状不一时可能弱提示（删除路径相对完整）

#### R9-A9 · Chart 空态文案可能误导（A · P2）

- `:746`「请先在资源配置中接入 Chart 仓库」— 实际创建走 **代码源** 拉 Chart，非 Helm Repo 集成；文案应对齐

## 3. 误报防范（B / C）

### B

| 项 | 依据 |
| --- | --- |
| OpenAPI `charts` 只读列表 | 外部集成 |

| 「工作流模板必须在中心创建」 | 产品可约定由工作流另存；但 release_plan 有完整 L3 CRUD，中心应可管 |

### C

| 项 | 澄清 |
| --- | --- |
| 「YAML 保存提示自动提取变量是假的」 | **基本误报**：后端 `CreateYamlTemplate`/`Update` 确会 `ExtractVariableYaml`；缺的是前端显式 extract API 调用 |
| 「Chart 保存『已从代码源同步』是假同步」 | **部分误解**：指从 Git 下载模板本体（Add/Update Chart），**不是** `SyncChartTemplateReference`；文案建议改为「已从代码源拉取」以免与服务同步混淆 |
| 「无 Dockerfile 校验」 | 保存时后端会 Validate；缺独立预检按钮 |
| 「Build 缺 pre_build」 | **误报**：创建/更新固定带 `pre_build: { res_req: 'low' }` |
| 「列表吞错」 | 有 `listError` 展示；workflow 列表抛错策略已注释对齐 P1-05 |
| AntD 废弃 / Math.random rowKey | lint 0；rowKey 用 id/name 合成 |
