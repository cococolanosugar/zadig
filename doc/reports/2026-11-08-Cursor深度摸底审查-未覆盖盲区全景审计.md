## 2. 缺陷清单

### P0 — 假操作 / 致命契约阻塞

#### BS-P0-1 · Plutus 页面为「可点击空壳」+ 幻觉列表路由

- **位置**：`frontend/src/pages/Plutus/index.tsx`
  - L25：`http.get('/api/plutus/products')` — L3 **无此路由**
  - L93–98：「新建客户」「新建交付项目」按钮无 `onClick`
  - L152：「交付控制台」链接按钮无导航
  - Tabs 仅改 `activeTab`，下方始终同一张 products 表
- **判定**：用户可见「请点击新建」空态 + 主 CTA，构成假操作面
- **建议**：要么下线路由/菜单并标 WIP；要么对接真实 Plutus 客户/交付 API（若仅 EE 私有服务，需明确 feature gate）；禁止无 handler 的 Primary 按钮

#### BS-P0-2 · 安装向导「激活企业许可证」POST 路由不存在

- **位置**：`frontend/src/api/installation.ts:51-52` → `POST /api/plutus-enterprise/license`
- **对照**：`pkg/microservice/plutus_enterprise/core/handler/router.go` 仅：
  - `GET /license`
  - `POST /signature/check`
  - `POST /license/upgrade/check`
- **影响**：Version 页激活主路径在对接本仓库 plutus-enterprise 时 **404/契约失败**；成功 toast 不会出现（错误通道存在），但产品承诺的 EE 激活断路
- **建议**：对齐真实 EE License 绑定 API（或 signature/check + 存储链路）；在 OSS 构建中隐藏/禁用激活并说明需商业组件

### P1 — 核心契约断裂 / 误导性数据

#### BS-P1-1 · Enterprise License 字段错配 + 假兜底文案 + 无导入

- **位置**：`api/enterprise.ts` GET `/api/plutus-enterprise/license`；`Enterprise/index.tsx` Descriptions
- **问题**：
  1. 前端读 `expire_time` / `license_type` / `company`；OSS stub 回 `expire_at` / `type`，无 `company`
  2. 空值兜底「KodeRover Community & Enterprise Evaluator」、特性 Tag 写死五枚
  3. 「更新 License 证书」仅 `feedback.message.info('请联系…')`，无上传/绑定
  4. 有效性判断要 `active|valid`，stub 为 `normal` → 易恒显未激活
- **建议**：字段映射对齐 `LicenseResponse`；去掉误导兜底；导入走真实 bind API 或明确「只读展示」

#### BS-P1-2 · Integration 多品类用列表 GET 冒充连通性成功

- **位置**：`Settings/Integration/index.tsx` `handleTestConnection` else 分支（~L315–318）及行内测试（~L478）
- **问题**：account/git/im/ai/gateway/monitor 等在 `http.get(listUrl)` 成功时提示「连通性测试通过」——仅证明列表 API 可达，**未验证第三方凭据**
- **建议**：无 validate 的品类禁用测试或改文案为「配置服务可达」；优先补后端 validate

#### BS-P1-3 · Dashboard 部署效能卡片注入硬编码 MTTR / 平均耗时

- **位置**：`Dashboard/index.tsx` ~L157–163（成功拼装）、~L311–317（null fallback 演示数）
- **问题**：`deploy/health` 仅有 success/failure，前端 invent `avg_duration_min: 4.2`、`mttr_min: 11.5`；无数据时甚至展示 128 次 / 98.4%
- **建议**：缺字段则不展示或显示「—」；禁止演示默认统计

#### BS-P1-4 · Directory 应用删除失败静默

- **位置**：`Directory/index.tsx` `handleDelete` ~L196–198 `catch { // Handled }`
- **建议**：与保存对称，`feedback.message.error(...)`

#### BS-P1-5 · KeyVault 缺少更新面（后端 PUT 已就绪）

- **位置**：`KeyVault/index.tsx` 仅 POST 新建 + DELETE；`router.go` 有 `PUT /items/:id`
- **建议**：编辑 Modal → PUT；敏感值更新策略与列表脱敏一致
